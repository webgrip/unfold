# Unfold: from clear to memorable

This is an illustrative case from October 2026, not a reusable layout specification or a conversion study.

Unfold is an experimental open-source, self-hosted system for agent work with human review. Its existing identity used Archivo, paper and ink colours, a red accent and a generated folded-plane mark. The design had to preserve the distinction between implemented paths and an incomplete architecture migration, and between current self-hosting and planned hosted offerings.

The first redesign made the workflow and technical evidence easier to understand. The user's feedback was that it still did not “pop.” The successful second pass changed the composition: oversized “Agents work. You decide.” type, a connected folded-paper evidence object, an immersive dark inspection chapter, a brief red human-decision chapter and an enlarged original wordmark. The user approved that implementation. This is evidence of acceptance by the requester, not measured audience conversion.

## What research changed

Physical-product and event references suggested selective exaggeration: one recognizable object can dominate while surrounding details remain precise. Developer-tool references supplied the discipline of placing a memorable premise beside an explicit category and inspectable evidence. The result used Unfold's own work artifacts and brand rather than borrowing another company's interface or claims.

Reference families included [Teenage Engineering](https://teenage.engineering/products/op-1), [Stripe Sessions](https://stripesessions.com/), [Nothing](https://nothing.tech/) and [Daylight](https://daylightcomputer.com/) for composition; [Kernel](https://www.kernel.sh/), [Zed](https://zed.dev/) and [Warp](https://www.warp.dev/) for technical storytelling; [Sentry's design account](https://blog.sentry.io/sentry-has-a-bold-new-look/), [Vercel's product tour](https://vercel.com/blog/designing-the-vercel-virtual-product-tour) and [Stripe's historical Connect account](https://stripe.com/blog/connect-front-end-experience) for material, self-paced interaction and spatial explanation. These references evolve; revisit them before using them as current evidence.

## Product truth created the visual material

The scene exposed a real recorded rounding fixture: one changed file, failing checks before the change, passing checks afterward, independent reviewer checks, zero model calls, zero model spend and no merge. It was labelled a recorded local demonstration. Its duration was not presented as a productivity benchmark, nor its zero spend as a production price.

The motion opened the same evidence object rather than decorating unrelated content. A finite desktop fold had an explicit replay; narrow screens used a manually selectable, front-facing paper. Reduced motion retained the full visual identity. The evidence explorer offered direct selection and interruptible playback. No new visual framework or synthetic hero image was needed.

## What verification established

The retained local build had 65 passing site tests and ten pages with no reported axe findings. Single retained Lighthouse desktop/mobile samples scored 100 for performance, accessibility and best practices; mobile LCP was about 1.88 seconds with CLS 0.015. The test origin was intentionally non-indexable. These are dated lab observations, not a guarantee for future builds or a formal accessibility claim.

Browser checks covered English/Dutch, light/dark, widths from 320 to 1440 pixels, enlarged text, keyboard interaction and responsive focus continuity. The interactive browser used reduced motion; normal-motion behavior was checked through source and default lab execution, not a separate manual animation review. No physical-device study, Firefox/Safari validation, screen-reader user study, field INP or browser-disabled-JavaScript exercise was claimed.

The durable lesson is to amplify the product's own consequential object, make the static composition strong, and test the seams where motion, focus, content and responsive layout meet.
