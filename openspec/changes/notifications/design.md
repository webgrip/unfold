# Design — notifications

## Context

- System ADR-0026 (proposed) decides server-side notifications, ntfy first
  then Web Push, only to people who can read the Team. This change builds
  that notifier; the shell cache and the triage view stay open.
- System ADR-0050 (PR #697) rule 1: channels are a registry. Slack and Teams
  arrive as adapters.
- Outbound webhooks follow Ploeg's audit events from a cursor and have a
  catalogue (`work_item.needs_you`, `work_item.ready_for_review`,
  `run.finished`, `client_sign_off.recorded`). The notifier classifies Ploeg's
  events with that catalogue's `ploegEventType`, so both name an event the
  same way, but it keeps its own cursor. The webhook outbox is written only
  while an active subscription exists and is pruned once delivered, so
  notifications for people cannot depend on it. `question` and `budget` have
  no catalogue type and are derived from the Work Item's facts.

## Decisions

- **D1 Triggers.** `needs_you`: Ploeg `work_item.needs_human` or
  `work_item.stale`. `question`: the same `needs_human` when the latest Shift
  closed `question_for_person`, and a pending Linked Session tool-permission
  request (its owner only). `review`: `work_item.awaiting_review`.
  `sign_off`: a current row in `client_sign_offs`. `budget`: after a Run's
  `outcome.*`, the latest Shift's spent plus held over its budget crosses a
  configured share (0.8 and 1 by default).
- **D2 Recipients** are people with stored preferences, read from the store,
  for whom `PloegClient.allows` and `TenantScope.reachesWorkItem` hold.
- **D3 Dedupe key** is the trigger and its occurrence (Ploeg event id,
  permission id, Sign-off id, Shift and share), unique per person, channel and
  target in the outbox.
- **D4 ntfy topic** is generated by Unfold (`unfold-` and 128 random bits), so
  it is not guessable on a server that allows anonymous reads. Publishing
  uses ntfy's JSON publish.
- **D5 Web Push endpoints** must be HTTPS on a public address; Unfold checks
  the address again at connection time.
- **D6 Retries**: 30 s, 2 min, 10 min, 30 min, 2 h, 6 h; a notice older than
  24 hours is given up. ntfy and push 429 and 5xx retry; other 4xx are final.

## Open Questions

- Should a person also be told about Work Items of Teams they read but did
  not start? Today every reader is a recipient, as ADR-0026 says.
- Tenant export exports preferences and each person's subscriptions by
  channel and date. The ntfy topic, the push endpoint and its keys work as
  credentials, so they are left out, as are VAPID keys and the ntfy token.
