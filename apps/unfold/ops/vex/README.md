# OpenVEX statements

Reviewed exploitability statements for findings the release gate should not count. Each statement is scoped to one image at one digest, carries a status and a justification from the OpenVEX vocabulary, and is attested onto the image by the signing step. Harbor's project allowlist stays empty; a suppression without a statement here does not exist.

Both images start at a budget of zero critical and zero high findings in `enforce` mode, as recorded in [ops/security/cve-budgets.yaml](../security/cve-budgets.yaml). The measured state on 2026-09-10 was zero findings at every severity. On 2026-09-27 and 2026-10-03 the image carried statements for CVE-2026-85091 (zlib) and CVE-2026-93748 / GHSA-ch52-4w7c-c8xp (npm's bundled http-cache-semantics). They were removed on 2026-10-18 once rc.92 shipped the fixed zlib 1.3.2-r1 and http-cache-semantics 4.3.0, and grype found neither without them. On 2026-10-18 rc.86 found CVE-2026-77214 (libexpat 2.8.5, High). The fix, libexpat 2.9.0-r0, is in Alpine 3.24 but not yet in dhi.io's mirror. The only program in the image that loaded libexpat was `git-http-push`, git's WebDAV push for dumb HTTP remotes, which agents never use, so the image build deletes it and a statement recorded the finding as `not_affected`. On 2026-10-27 the image carried libexpat 2.9.0-r1 from dhi.io, grype no longer reported CVE-2026-77214, and the statement and its build check were removed; the build still deletes `git-http-push`.

On 2026-10-27 rc.118 found CVE-2026-92392 (libcurl 8.22.0-r1, High): a use after free when an HTTP/2 server resets an upload stream. Git links libcurl and agents push over HTTPS, so no statement applies. The fix, libcurl 8.23.0-r0, is in Alpine 3.24 but not in dhi.io's repository (built 2026-10-27T05:42Z). The [agent image](../agent/Dockerfile) installs that one package from Alpine's signed `v3.24/main` repository; the version constraint fails the build if Alpine withdraws it. Remove that line once dhi.io carries libcurl 8.23.0 or later.

Add a statement only after a rebuild on a patched base cannot remove the finding, and reference the [infrastructure VEX guide](https://forgejo.webgrip.dev/webgrip/infrastructure/src/branch/main/ops/vex/README.md) for the file shape.
