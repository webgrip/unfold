# VS Code 1.141 against Unfold: AHP 1.0, two breaks queued for 1.142, and what to use

Research date: 2026-10-08. This dossier follows [the 1.140 dossier](2026-10-01-vscode-1-140-fit.md) and [the shared-surface record](../../../../docs/research/2026-10-01-vscode-surface-and-agency-fit.md) to the [1.141 release](https://code.visualstudio.com/updates/v1_141) of 7 October 2026. It asks what 1.141 changes for Unfold and Ploeg, what is already queued after it, and which surfaces are worth using.

Sources:

- the release notes in [raw markdown](https://github.com/microsoft/vscode-docs/blob/main/release-notes/v1_141.md) and every page they link;
- `microsoft/vscode` at tags 1.140.0 (`07f806f9`) and 1.141.0 (`2a59476c`), and at main `d3d31f62` (2026-10-08), which already reports 1.142.0;
- the [AHP repository](https://github.com/microsoft/agent-host-protocol) at `13277064` (2026-10-03);
- the VS Code 1.141.0 stable bundle installed on the owner's macOS machine;
- this repository at `91cd503b`.

**Method.** Five research agents ran in parallel: documentation and roadmap, the agent host and AHP client in source, the extension API, ecosystem and absence checks, and a read-only sweep of this repository. The AHP tags, the bundle and [`host.ts`](../../src/ahp/host.ts) were then checked first-hand. Evidence read in the shipped build is marked **(build)**, in source only **(source)**. Everything else carries its link.

**Landing.** No protocol-research contract block exists in `AGENTS.md`, so the destinations follow the 1.140 dossier: this dossier, a dated sentence on the AHP row of the [protocol ledger](2026-09-11-ecosystem-alternatives.md#appendix-adjacent-components-and-communication-protocols), a dated update to [ADR 0012](../adrs/0012-agent-host-protocol-host.md), and a dated note on the shared-surface record. Ploeg backlog item 101 lives in `ploeg-hq/ploeg` ([ADR-0019](../../../../docs/adr/adr-0019-unfold-pins-ploeg-from-its-own-repository-and-releases-only-its-application.md)), so its re-confirmation is recommendation 11 rather than an edit here.

## Verdict

1.141 adds no extension API and changes nothing in Unfold's architecture. **(source)** `vscode.d.ts` is byte-identical between the two tags, and no proposal was added or removed. What matters sits around the release:

1. **AHP 1.0.0 shipped on 2026-10-02.** Its versioning rule keeps `0.9.x` as one of two compatibility baselines, so Unfold's host is still a conforming 0.9 host.
2. **VS Code 1.142 will send the host two things it rejects.** Both are merged on main. VS Code now ships weekly, and milestone 1.142.0 is due on 2026-10-12. Read state moves to `chat/isReadChanged`, and new sessions arrive as `ahp-session:/<uuid>`, which the host re-advertises as `unfold:/<uuid>`.
3. **The record is behind the code.** Seven of the fifteen 1.140 findings, both cross-user leaks among them, were fixed on 2026-10-01 in `5ecd610e` and `78d4d6fd`, minutes after that dossier was committed. ADR 0012 and the ledger still said the host leaks and cannot run a session. This change corrects both.
4. **GitHub is building its own AHP hosts.** Copilot cloud sandboxes speak AHP over an Azure Web PubSub relay, `copilot --ahp-host` hosts sessions, and main adds "Mission Control" environments. AHP gains a second production implementation, and it is still Microsoft's.

The surfaces worth using are small:

- Extension-provided MCP servers now demonstrably reach all three agent-host harnesses, with a credential caveat.
- The host can block input and annotate sessions through `_meta` keys that VS Code reads from any host.
- GitHub Enterprise sign-in shows a finalized pattern for one authentication provider serving several issuers.

Everything else in 1.141 is orthogonal, or a design reference at most.

## What 1.141 actually is

The release "makes it easier to manage agent sessions, protect agent workflows, edit columnar text, and work across GitHub Enterprise instances" ([notes](https://code.visualstudio.com/updates/v1_141)). The Copilot harness, built on the [Copilot SDK](https://github.com/github/copilot-sdk), is "gradually becoming the default for enterprise users who have VS Code experiments enabled". Most of the release serves it:

- local sandboxing of its terminal commands, MCP servers and language servers;
- worktree cleanup, and automatic "mark as done" for sessions whose GitHub pull request merged;
- a session grid, filters by environment, harness and "Created In", and per-chat unread state;
- live pickup of Copilot CLI and Copilot app conversations, and Codex chats continued from the ChatGPT app or Codex CLI;
- unified managed settings for the sandbox, telemetry identity and policy refresh;
- several GitHub Enterprise instances in one window.

The notes carry no "Extension authoring" or "Proposed APIs" section, and none is missing. **(source)** `src/vscode-dts/vscode.d.ts` has blob `60447c2a` at both tags, and the 182 proposed `.d.ts` files are the same set. Five proposals changed in content: `chatParticipantPrivate`, `chatParticipantAdditions`, `languageModelCapabilities`, `languageModelThinkingPart`, and a comment in `authIssuers`. None is usable from an Open VSX extension ([ADR 0021](../adrs/0021-the-extension-ships-through-open-vsx-first.md)).

Reception was quiet. The VS Code blog has had no post since 2026-09-23, and no Hacker News story covered 1.141. The loudest feedback concerns the Copilot harness removing per-change Keep and Undo ([vscode#339363](https://github.com/microsoft/vscode/issues/339363), 50 comments: "We need _more_ control … not _less_"). It matters to Unfold as a market signal for review-first work.

### AHP 1.0.0, and VS Code's private 0.10.0

- AHP tagged `v1.0.0`, `spec/v1.0.0` and its TypeScript, Rust, Kotlin, .NET and Go packages at `5f16d81b` on 2026-10-02 (checked first-hand). `@microsoft/agent-host-protocol@1.0.0` is on npm. Development continues as 1.1.0, which is still empty.
- The [versioning rule](https://microsoft.github.io/agent-host-protocol/specification/versioning) says "hosts accept `>=1.0.0 <2.0.0` or `>=0.9.0 <0.10.0`, regardless of offer order". The host returns the exact offered string. A failed match answers `-32005` with `data.supportedVersions`, where a range such as `^0.9.0` is allowed. The repository now ships 22 negotiation test vectors in `types/test-cases/version-negotiation.json`.
- The 1.0 blocker [#366](https://github.com/microsoft/agent-host-protocol/issues/366) closed on 2026-10-01. A server SDK is still absent. [#422](https://github.com/microsoft/agent-host-protocol/issues/422) is open with no comments, and the TypeScript package's `./hosts` export is a client for several hosts, not a server.
- CODEOWNERS is still `* @connor4312 @roblourens`. Every commit since the 1.140 sweep came from Microsoft staff or bots. Outside activity is limited to open pull requests such as [#502](https://github.com/microsoft/agent-host-protocol/pull/502), which lists the third-party `hydra-ahp` host.
- [#491](https://github.com/microsoft/agent-host-protocol/issues/491) (open) reports that eight actions absent from `spec/v0.9.0` are registered as introduced in 0.9.0. They include `chat/isReadChanged`, `chat/isArchivedChanged` and `chat/backgroundWorkSet`. A peer that trusts the registry sends them on a 0.9.0 connection. That is the mechanism behind break A below.
- **(build)** VS Code 1.141.0 speaks `PROTOCOL_VERSION = '0.10.0'` and offers `0.10.0, 0.9.0, 0.7.0, 0.6.0, 0.5.2, 0.5.1`. Upstream never released 0.10.0. VS Code main says its "0.10.0 release shares the wire contract of the upstream baselines" and offers `1.0.0, 0.10.0, 0.9.0` ([vscode#340393](https://github.com/microsoft/vscode/pull/340393), merged 2026-10-08).
- Unfold's host accepts `/^0\.9\.\d+$/` (`host.ts:564`), so it still negotiates with 1.141 and with main.

New in 1.0.0, by exact name:

- `chat/backgroundWorkSet` and `chat/backgroundWorkRemoved`, with `ChatState.backgroundWork` holding `shell` or `subagent` entries;
- `chat/isReadChanged` and `chat/isArchivedChanged`, projected as status bits 32 and 64, which replace the unreleased catalog fields `isRead` and `archived`;
- `SessionChatSummary.status`, `.changes` and `.interactivity`, and `SessionSummary.chats` and `.defaultChat`;
- `ChatState.changesets`, the `moveChat` command, and experimental canvas channels (`ahp-canvas:`);
- `AuthenticateParams.expiresIn`, automation `disableConditions` and `customizations`, and `McpServerStartingState.blocking`.

1.141 adds one item the 1.140 list missed:

- **C16, the `root/configChanged` echo.** **(source)** On every connect the client dispatches `root/configChanged` to every host, with no schema guard (`agentHostProtocolClient.ts@1.141.0:1251-1260`). The payload includes workspace trust with its trusted folder URIs, the telemetry level and terminal auto-approve rules. The host finds no session for the root channel and rejects the action. The rejection carries the payload back to the same user's other attached clients (`host.ts:164-168,671-672`). Since `5ecd610e` it no longer crosses users, but it still copies one machine's trusted folders to the user's other machines.

Of the 1.140 recommendations, the archive actions (1) and version negotiation (2) are still open. `vscode://agents/new` (3) is not built. The nearest shipped thing is `vscode://webgrip.unfold/checkout`, added in `b7be09a4`.

## Two breaks queued for 1.142

Both come from pull requests merged on VS Code main, and both are confirmed in source at `d3d31f62`. Neither is in the 1.141 bundle.

**A. Read state.** Main moves `ChatIsReadChanged` from `'0.10.0'` (`registry.ts@1.141.0:148`; **(build)** the same in `sessions.desktop.main.js`) to `'0.9.0'` (`registry.ts@main:166`), matching upstream. Marking a session read or unread then sends `chat/isReadChanged` on a 0.9.0 host's default chat channel, where 1.141 sent `session/isReadChanged`. The host accepts only the latter (`host.ts:699`), so it rejects the action and read state rolls back.

**B. Session URIs.** Main's `newAgentHostSessionUri` carries the rule "Unmarked conforming hosts use AHP addressing; only a positively identified older native host needs legacy creation" (`agentHostSessionIdentity.ts@main:13-15`). A host that sends neither `_meta["vscode.agentHost"]` nor root `_meta.hostBuild` counts as unmarked, so its new sessions arrive as `ahp-session:/<uuid>`. Unfold's host parses that form (`host.ts:31`) and keeps the id. It then advertises `unfold:/<uuid>` in `root/sessionAdded` (`host.ts:601`) and in every later summary (`host.ts:185`). The client keys sessions by the exact resource string, so it will likely show an orphaned draft beside the real session. This is inferred from source and needs a live check.

The fix for B is to advertise the URI the client chose, verbatim, in every summary and notification. Sending `vscode.agentHost` to look native would be wrong, because it also turns on native chat-URI derivation. Existing sessions are unaffected: main resolves an unknown session through `listSessions`.

## What VS Code reads from any host

The 1.141 client reads several `_meta` keys from every AHP host, not only its own, and it sends or answers a few requests outside the specification. None of them is in the AHP specification. Each is a cheap lever, and each is undocumented and may move.

| Key or method | Carried in | Effect | Use for Unfold |
| --- | --- | --- | --- |
| `vscode.session.initiator` `{name, title?, version?}` | Session summary `_meta` | Sets "Created In" | Leave unset. Any value other than VS Code is hidden by default outside the cloud environment (`sessionsListFilters.ts@1.141.0:101-106`). |
| `vscode.external` | Session summary `_meta` | Marks a session as external | None. Unfold sessions are not external. |
| `vscode.chatInputState[<chat>]` set to `{kind: 'blocked', error}` | Session state `_meta` | Blocks input with a banner and Retry | A read-only Work Item projection (PV-081) could block input instead of rejecting turns. |
| `vscode.sandboxDiagnostics` | Session state `_meta` | Shows "Sandboxing is unavailable in this environment" with reasons | None today. |
| `copilot.usageDetail`, `copilot.errorDetail`, `copilot.usageInfo` | Turn and usage `_meta` | Rendered for any host by readers vendored from `github/copilot-host` | A lead for showing Ploeg's spend where VS Code shows usage. How it renders is unverified. |
| `vscode/requestMcpAuthentication` | Host-to-client request | Asks the client to authenticate an MCP server for an unattended session | None today. |
| `getNetworkDiagnosticsInfo`, answered with `{version, os, arch}` | Client request after each connect | Chooses the path formatter | Answering `{os: 'linux'}` gives POSIX path labels. Today's method-not-found costs only a log line. |

When a tool call carries none of VS Code's own `_meta`, the client also labels the row from a Copilot table keyed by tool name (`bash`, `view`, `edit`, `write_file`, `search` and others). Unfold tool events that use those names get Copilot's wording.

## The one scenario where this could matter more

The 1.140 dossier named it: Ploeg Work Items projected as read-only AHP sessions (PV-081), so that the Agents window becomes a second "Needs you" inbox. AHP 1.0 makes that projection fit better than it did:

- A **Shift** maps to a session and each **Run** to a peer chat in it. Per-chat unread state and `modifiedAt`, which 1.141 now tracks for nested sessions, tell a person which Role's Run changed.
- A Run in progress maps to a `subagent` entry in `ChatState.backgroundWork`, which needs no terminal.
- Input is either blocked with `vscode.chatInputState`, or accepted as an instruction for the next Run. The second is what [ADR 0023](../adrs/0023-unfold-submits-work-to-ploeg-and-never-executes-it.md) proposes for steering.
- When Ploeg sees the pull request merge, on any forge, the host sets the archived bit. Every forge then gets the "done when merged" outcome that VS Code builds only for GitHub.

The tension is unchanged. ADR 0023 is still proposed, with a review date of 2026-10-23, and its open question 6 asks whether the AHP host is retired or kept for another purpose ([design proposal](../ploeg-front-end.md)). A chat per Run also needs the host to advertise `multipleChats`, which `78d4d6fd` deliberately stopped doing. It also needs the host to negotiate 1.0 rather than rely on VS Code's registry (AHP#491). The scenario is input to that decision, not a reason to pre-empt it.

## What comes after 1.141

VS Code now ships weekly. Monthly iteration plans stopped after [#293855](https://github.com/microsoft/vscode/issues/293855) in February 2026, and the [Roadmap wiki](https://github.com/microsoft/vscode/wiki/Roadmap) still covers 2023/24. The only dependable forward view is main and the [1.142.0 milestone](https://github.com/microsoft/vscode/milestone/458), due 2026-10-12. The draft notes are dated 2026-10-14.

Merged on main as of 2026-10-08:

- **AHP 1.0 negotiation.** The client offers `1.0.0, 0.10.0, 0.9.0` and drops 0.8 and older ([#340393](https://github.com/microsoft/vscode/pull/340393)). VS Code's own host accepts 0.9, 0.10 and 1.0 clients ([#340125](https://github.com/microsoft/vscode/pull/340125)).
- **AHP session URIs and chat read state**, the two breaks above.
- **Session links for remote hosts.** `vscode://agents/agent-host-session/…` gains `connectionAuthority` and `session` query parameters, so a link can name a remote host. That makes 1.140 recommendation 4, a browser link into the Agents window, testable once 1.142 ships.
- **Mission Control environments.** `chat.agentHost.remoteConnections`, set to `devTunnel` (the default) or `missionControl`, can register the native host with GitHub over Azure Web PubSub for the iOS and Copilot app clients ([#339513](https://github.com/microsoft/vscode/pull/339513)). The setting's own description says "conversation content is not end-to-end encrypted". `chat.agentHost.cloudSandbox.enabled` now selects "GitHub Cloud" ([#340150](https://github.com/microsoft/vscode/pull/340150)).
- **BYOK models in the Copilot harness**, on by default but local only ([#339931](https://github.com/microsoft/vscode/pull/339931)).
- **`set_workspace` and `isolate_session`**, which move a chat to another folder or a new worktree ([#339778](https://github.com/microsoft/vscode/pull/339778)).
- **Forwarded MCP servers** move into a separate "standalone" customization bundle.
- **The Windows sandbox** moves to `@microsoft/mxc-sdk` 1.0.0 ([#340188](https://github.com/microsoft/vscode/pull/340188)).

Not moving:

- `authIssuers`, `chatSessionsProvider` and `agentsWindowActivation` are still proposed, and no proposal changed between 1.141.0 and main.
- Two extension-API items carry the 1.142 milestone, both as proposals: URL-opening hooks ([#109277](https://github.com/microsoft/vscode/issues/109277)) and contributable chat context ([#271104](https://github.com/microsoft/vscode/issues/271104)).
- `vscode://agents/new` still takes only `prompt` and `workspace` on main.
- `chat.remoteAgentHosts` and its address parser are byte-identical at all three refs, and `chat.remoteSessions.tools.enabled` still defaults to false.

Outside VS Code:

- opencode, Ploeg's default ACP profile, has an open request for native AHP ([anomalyco/opencode#53836](https://github.com/anomalyco/opencode/issues/53836)).
- Two community hosts now put any ACP agent behind AHP: [`@ahpd/agent-acp`](https://www.npmjs.com/package/@ahpd/agent-acp) (0.10.0, 2026-10-07) and [`smagnuso/hydra-ahp`](https://github.com/smagnuso/hydra-ahp) (created 2026-10-05; it negotiates 0.9.0 and serves 1.0.0). Each has at most three stars.
- LiteLLM merged `litellm.agent()`, which runs Claude Code, Codex and opencode through the gateway with a per-session token and a sandbox ([BerriAI/litellm#43885](https://github.com/BerriAI/litellm/pull/43885)). It overlaps with Ploeg's Run execution and belongs in the [market landscape](market-landscape.md).

## Recommendations

Ordered by urgency.

1. **Before 1.142 reaches Stable (due 2026-10-12), make the host accept what main sends.** Accept `chat/isReadChanged` on the default chat channel, echo it, and keep status bit 32 on the session and its chat (break A). Advertise the client-chosen session URI verbatim in `root/sessionAdded`, `listSessions` and every summary (break B). Add a test to [`ahp.test.ts`](../../test/ahp.test.ts) that replays main's sequence with an `ahp-session:/` URI.
2. **Finish the 1.140 archive recommendation, and accept `root/configChanged`.** Accept `session/isArchivedChanged` and `chat/isArchivedChanged`, keep bit 64, and stop resetting both bits in every summary (C13). Accept `root/configChanged` and discard its payload (C16). Persistence stays with PV-048.
3. **Negotiate by the AHP 1.0 rule.** Return the highest offered `0.9.x` as the exact string, reject malformed entries, and test against the upstream vectors. Implement it natively, because `ws` is the only permitted runtime dependency ([ADR 0036](../adrs/0036-the-agent-host-speaks-websocket-through-ws.md)). Negotiating 1.x is a later step: it obliges the host to publish `SessionSummary.chats` and the chat status bits.
4. **Run one live session from VS Code 1.141 before building more on the host.** Every finding in two dossiers comes from reading code. Attach with **Attach as Agent Host**, create a session, send a turn, answer a permission request, mark the session read and done, and reconnect.
5. **Correct the record.** Done in this change, with a dated update on ADR 0012 and a dated sentence on the ledger row.
6. **Decide credential delivery before the extension provides `ploeg-mcp` (VIK-1653).** **(source)** VS Code forwards only the definition returned by `provideMcpServerDefinitions` and never calls `resolveMcpServerDefinition` for agent-host delivery. It then writes `env` values and headers in plaintext to `{userDataPath}/agentPlugins/<key>/<nonce>/.mcp.json`. Phase 1 of [ADR-0011](../../../../docs/adr/adr-0011-unfold-is-reachable-over-mcp-through-a-read-first-server.md), a stdio server with a token in its environment, would therefore leave the token on disk. Two shapes avoid that. Either the stdio server reads its own credential from the OS keychain, or `ploeg-mcp` is an HTTP server with RFC 9728 protected-resource metadata, which the agent host resolves through VS Code's authentication (`agentHostAuth.ts@1.141.0:920-1054`). The documented limit "only local MCP servers that don't require authentication" appears nowhere in source, so test each harness. A sandboxed Copilot session also blocks a local server's localhost and LAN traffic by default.
7. **Accept GHE.com in the GitHub task source.** Allow `https://api.<subdomain>.ghe.com` with an empty path in [`tasks.ts`](../../src/tasks.ts) line 54. 1.141 treats an estate of GHE.com plus GitHub Enterprise Server as normal, and the agency phase will meet one.
8. **Leave `vscode.session.initiator` unset.** Setting it hides Unfold's sessions by default. The Environment filter already separates them by host name.
9. **Use the GitHub Enterprise pattern for the extension's own account (VIK-1656).** **(source)** The finalized way to serve several issuers is one `AuthenticationProvider` with `supportsMultipleAccounts: true`, the issuer in the account label (`octocat - octocat.ghe.com`), and consumers that select a session by `{ account }`. `authIssuers` remains proposed and unusable on Open VSX. A per-Tenant Authentik issuer fits the same shape.
10. **Verify two Agents-window behaviours.** **(source)** A `vscode://webgrip.unfold/checkout` link goes to the last-active window. When that is the Agents window, where third-party extensions are disabled, VS Code tries to install and enable the extension there (`extensionUrlHandler.ts@1.141.0:274-283`). Also check whether the user setting `extensions.supportAgentsWindow` with `{"webgrip.unfold": true}` shows the Now view in the Agents window. If it does, add it to the walkthrough.
11. **Re-confirm Ploeg backlog item 101 in `ploeg-hq/ploeg`.** Its first gate, "AHP ≥ 1.0", is met. Its second, "a production non-Microsoft host", is not: the only production host outside VS Code is GitHub's, and the community hosts are days old. Re-confirm [Ploeg ADR 0006](../../../ploeg/docs/adrs/0006-ahp-is-the-wrong-layer.md) at its 2026-10-31 review.
12. **Treat stacked pull requests as input to ADR-0010's follow-up split, not as a feature.** If a follow-up Work Item branches from its predecessor's head, GitLab 19.1 shows the chain as a stack from branch topology alone, GitHub needs one `POST /stacks` call, and Forgejo shows separate pull requests. Ploeg has no GitHub forge provider today.
13. **Claim the `webgrip` namespace on Open VSX.** `GET https://open-vsx.org/api/webgrip` returned `verified: false` on 2026-10-08. Open VSX's namespace-ownership check, enforced since its v1.2.0 deploy on 2026-09-29 ([production configuration](https://github.com/EclipseFdn/open-vsx.org/blob/aws-main/configuration/application-production.yml)), skips extensions that are already active. It finds a Marketplace publisher only through extensions that publisher has published, and `WebGrip` ([ADR 0021](../adrs/0021-the-extension-ships-through-open-vsx-first.md)) has published none. So new versions of `webgrip.unfold` are not at risk, which is why rc.44 and rc.45 went through. A new extension name in `webgrip` could be quarantined once `WebGrip` publishes on the Marketplace. Claiming still removes the unverified-publisher warning, and Open VSX asks for it once the extension exists on the Marketplace.
14. **Keep `engines.vscode` at `^1.99.0` and feature-detect new APIs.** Fork bases run from 1.107 (Antigravity, Trae) to 1.141 (code-server). The MCP provider API needs 1.101 and `chatSkills` needs 1.109. Guarding those calls keeps every fork.
15. **Adopt nothing else.** The sandbox is desktop-local and Copilot-only. The Copilot harness, the Codex handoff, worktree cleanup and the grid serve VS Code's own harnesses. GitHub's Mission Control is GitHub-hosted and GitHub-only.

## Smaller leads and design references

- **Blobby's achievements** ([source](https://github.com/microsoft/vscode/blob/1.141.0/src/vs/workbench/contrib/chat/browser/chatPetAchievements.ts)) reward behaviour rather than volume. "Trust but Verify" is earned by opening agent changes for review, and "Ship it" by creating a pull request. A locked card shows its hint and reward but hides its name. A new unlock stays marked "New" until opened, and a gold star sits on the pet for ten seconds. Unlocks count only while the pet is enabled, and they sync through user storage. These are references for Run card binders ([ADR 0029](../adrs/0029-binders-packs-and-pulls-collect-run-cards-privately-and-fairly.md)) and private unlocks ([ADR 0033](../adrs/0033-a-forge-card-s-art-window-is-an-inner-world-its-holder-may-decorate-privately.md)). Rewarding review rather than volume also keeps a collection from turning into a throughput metric.
- **MXC's policy vocabulary** (`userPolicy.filesystem` with `readwritePaths`, `readonlyPaths` and `deniedPaths`; `userPolicy.network` with `allowOutbound`, `allowLocalNetwork`, `allowedHosts`, `blockedHosts` and `proxy.url`) is worth comparing with Ploeg's executor network profile when Ploeg ADR-0037 reaches the chart.
- **The Copilot harness backlash** over the removed per-change Keep and Undo is evidence that some VS Code users want more review control. Unfold sells review-ready pull requests.
