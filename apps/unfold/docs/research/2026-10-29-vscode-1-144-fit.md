# VS Code 1.144 against Unfold: the protocol goes public and the competition consolidates

Research date: 2026-10-29. This dossier follows [the 1.143 dossier](2026-10-23-vscode-1-143-fit.md) to the [1.144 release](https://code.visualstudio.com/updates/v1_144) of 2026-10-28, the day GitHub Universe opened. It asks what 1.144 changes for Unfold's Agent Host Protocol (AHP) host and its VS Code extension, what it newly makes possible, what the protocol and plugin ecosystem did around it, and how the competitive field looks after a month of acquisitions and launches.

Sources:

- the [1.144 release notes](https://code.visualstudio.com/updates/v1_144) and the 1.145 Insiders draft;
- `microsoft/vscode` diffed at tags 1.143.0 (`2d0b7506`) and 1.144.0 (`2c33b50b`), plus the shipped 1.144.0 Linux bundles;
- the [AHP repository](https://github.com/microsoft/agent-host-protocol), the [Agent Plugins specification](https://github.com/agentplugins/agent-plugins-spec) and GitHub's Universe changelogs;
- vendor documentation for twenty competitors;
- this repository at `origin/development` `03bfd2fa`.

**Method.** Four research agents ran in parallel. The claims that drive a verdict were then re-checked first-hand: the approval-policy seeding, quick-chat comparisons, the working-set changeset, the Copilot managed-settings key, Ona's shutdown, Claude Code's self-hosted environments, Copilot approvals, OpenHands' Forgejo code, the Cursor sale and AHP [#534](https://github.com/microsoft/agent-host-protocol/pull/534). Evidence read in code is marked **(source)**; everything else rests on documentation or changelogs. Nothing was run against Unfold's host.

**Landing.** This dossier, an [ADR 0012](../adrs/0012-agent-host-protocol-host.md) update, a dated sentence on the AHP paragraph of the [protocol ledger](2026-09-11-ecosystem-alternatives.md#appendix-adjacent-components-and-communication-protocols), the [watchlist](2026-10-13-protocol-integration-gaps.md#watchlist) (T13, T14, T18 and T23 to T28 updated, T29 to T33 added), and the restated market position in [the market landscape](market-landscape.md), [the go-to-market plan](../product/go-to-market.md) and [the surface and agency fit record](../../../../docs/research/2026-10-01-vscode-surface-and-agency-fit.md). The working page the owner reviewed this from is a private artifact; this file is its durable copy.

## Verdict

1.144 breaks nothing in the host. It lets organisation policy reach the approval picker of Unfold sessions, offers Compare Models where Unfold can only refuse it, and adds five opt-in host surfaces, of which conversation import is the one worth a spike. Around it, the protocol caught up with Ploeg's Roles and two of Unfold's four market claims stopped holding.

1. **Nothing breaks.** **(source)** The client still offers AHP `1.0.0, 0.10.0, 0.9.0`, `PROTOCOL_VERSION` is still `'1.1.0'`, the only initial subscription is still `ahp-root://`, and every `vscode.*` key in the diff is an addition. The notes' "Agent Host Protocol v1.0" is the public specification and library release of 2026-10-02, not a new wire version.
2. **Organisation policy now reaches into Unfold sessions.** **(source)** The new `ChatDefaultConfiguration` policy seeds the approval level of every agent-host provider's new sessions. Unfold's session config names its property `approvalMode` with the values `manual` and `allow-all`, which are Copilot's own names, so VS Code writes an organisation's allow-all straight into it, or forces `manual` when policy restricts auto-approval. Ploeg's Team policy still decides, because the host offers `allow-all` only where the placement permits it. Nothing pins that rule in a test yet.
3. **Five new opt-in host surfaces, none gated to Copilot.** **(source)** Chat workspaces for nested sessions (`vscode.createChatWorkspace`), importing a conversation into a new session (`vscode.createSessionImport`), worktree cleanup (`vscode.worktreeCleanup`), artifact integrations and agent extensions. Import matters most: VS Code no longer refuses to import a conversation into a remote host, which for Unfold is "hand this chat to Unfold" as a proposed Work Item.
4. **Compare Models now shows for Unfold's host, and it can only fail there.** **(source)** Comparisons are on by default. Folderless quick chats can be compared for any provider with `supportsQuickChats`, and the remote-host provider sets that to true. Unfold's config requires a repository, so those attempts cannot start. Repository comparisons still need an `isolation` property, which Unfold lacks. Unfold needs a clean refusal message, not a feature.
5. **Working-set Keep and Undo is generic.** **(source)** Any host that publishes a changeset of kind `working-set` with `accept-changes` and `discard-changes` gets inline Keep and Undo in the editor window. Unfold's edits live in a Ploeg pod behind an immutable candidate, so this joins the existing per-file discard spike rather than becoming a build.
6. **Every headline feature is Copilot-only or GitHub-only.** Cloud sessions, cloud automations, Fusion, image generation, computer use, canvases, Copilot Memory, Copilot connectors, GitHub Feed and the `/plugin` commands. The canvas gate is still the local `copilotcli` provider, and MCP forwarding still drops `oauth`. The Remote Environments dialog lists SSH, WSL, tunnels, GitHub Environments and Dev Containers, but not plain WebSocket hosts like Unfold. People can, however, hide Unfold from the environment picker.
7. **The protocol caught up with Unfold's shape.** AHP [#534](https://github.com/microsoft/agent-host-protocol/pull/534), merged on 2026-10-27, lets one session hold chats from different harnesses, which matches Ploeg's Roles. [#545](https://github.com/microsoft/agent-host-protocol/pull/545) and [#510](https://github.com/microsoft/agent-host-protocol/pull/510) open a path to remote canvases and app previews, and the 1.145 Insiders build previews web apps running on remote agent hosts. There is still no 1.1.0 release; the changelog heading is empty.
8. **GitHub opened nothing for third-party agents, but it opened a clean Copilot-as-harness path.** The only partner agents in GitHub are Claude and Codex, and no partner programme exists. New on 2026-10-27: a GitHub App with the "Copilot Requests" permission can drive the Copilot SDK with an installation token, billed to the organisation. That is the first sanctioned way for Ploeg to run Copilot without a person's login.
9. **Two of Unfold's four market claims no longer hold.** Tickets to review-ready pull requests is now sold by Copilot, Devin, Rovo Dev, GitLab Duo and Tembo, and OpenHands supports Forgejo (verified in its code). Three claims still hold: per agency across client forges, billing per accepted ticket, and the agency's client approving ready work. Self-hosting both the control plane and execution in the EU is now the sharpest difference: every large vendor's "self-hosted" option keeps the control plane and transcripts in its US cloud.
10. **Publishing.** Open VSX and the Marketplace both gained OIDC Trusted Publishing, but only from GitHub Actions; Forgejo Actions keeps its tokens. Azure DevOps global PATs retire on 2026-12-01, which matters if Unfold's `VSCE_PAT` is one.

## What 1.144 actually is

A Copilot and GitHub release timed with Universe. Around the agent host:

- **Agents.** Organisation-managed session defaults (`ChatDefaultConfiguration`); Compare Models on by default, folderless and without a remote; conversation import into a new session; nested sessions with their own workspace; an inline working set with Keep and Undo; moving chats between sessions; an environment-first session composer; a Remote Environments dialog; a disk-low suggestion for worktree storage; extensions in the Agents window.
- **Copilot and GitHub.** Cloud sessions and Cloud Automations, Copilot Fusion (single, cascade and critique), assisted permissions out of preview, canvases, computer use, image generation, Copilot Memory, Copilot connectors, voice, GitHub Feed and the `/plugin` commands.
- **Plugins and customizations.** Share links to plugins and customizations, a Marketplace Browse page and the `ChatCustomizationMarketplace` policy.
- **MCP.** OAuth tokens kept per server (`authenticate.target`).
- **Publishing.** Trusted Publishing to the Marketplace and Open VSX.
- **Workbench.** The modern UI, announced in the 1.143 blog, is the default.

**(source)** `vscode.d.ts` is byte-identical between the tags. New proposals are `chatArtifactIntegrations` and `github`; Stable's `product.json` allows no third-party extension to use the first.

## Deep dives

### Organisation defaults land in Unfold's approval picker

**(source)** `baseAgentHostSessionsProvider.ts` resolves a new session's config with the precedence "enterprise policy > remembered pick > effective configured value". `getSessionApprovalProperty` falls back to a property named `approvalMode` with Copilot's values, and `writeSessionApprovalLevel` maps `default` → `manual` and `autoApprove` → `allow-all`. Unfold's [`session-config.ts`](../../src/ahp/session-config.ts) uses exactly `approvalMode: ['manual', 'allow-all']`, and only `['manual']` when the placement cannot auto-approve. So the organisation's choice is honoured where the Team permits it and silently drops to `manual` where it does not. That is the right behaviour, but nothing pins it: a test should state that a client-sent `allow-all` is a request the Team policy can refuse, and the picker's description should say why the choice is locked. The same code reads an optional read-only `availableApprovalModes` array, which Unfold can use to say which modes the Team allows without lying in the enum.

### Compare Models, again

**(source)** `sessions.chat.compareAgents.enabled` went from false to true. `_shouldShowComparisonAction` in `newChatWidget.ts` now has two paths:

- folderless quick-chat comparisons, for any provider with `supportsQuickChats`, with no judge or synthesizer; `remoteAgentHostSessionsProvider.ts` sets it to true;
- repository comparisons, which still need an `isolation` enum that lists `worktree`.

Every attempt uses the draft's provider, so a comparison never mixes Unfold with Copilot. Unfold's config has `required: ['repository', 'team', 'budgetUsd']`, so a quick chat cannot start a session. What a person sees today when they pick Unfold in a folderless chat is unverified. The host should refuse with "Unfold works on a repository: pick one to start" rather than a generic error, and never start N paid Runs. The mirror stays Ploeg's bake-off ([ploeg-hq#220](https://github.com/ploeg-hq/ploeg/pull/220), ADR-0135, proposed).

### Hand a chat to Unfold

**(source)** With `vscode.createSessionImport`, VS Code can create a session on a remote host and pass the earlier conversation as turns; before 1.144 it refused remote targets. Unfold's rule for delegation from editors still applies: an import becomes a proposed Work Item waiting for a person, never a Run. The turns become the Work Item's context, with a hard cap and secret scrubbing before storage. This is the first native editor gesture for journey J3 of [the surface and agency fit record](../../../../docs/research/2026-10-01-vscode-surface-and-agency-fit.md). Still unverified: which menu entry offers a remote host as an import target in Stable.

### Extensions in the Agents window

**(source)** The manifest capability and the kill switch are unchanged. New are `agentsWindowManagement` and `agentsWindowSuggestions`, both off in Stable, and `agentsWindowAutoEnable` (default false), which only auto-enables extensions without views. Stable ships a 28-id `sessionsWindowAllowedExtensions` list without `webgrip.unfold`. There is still no API that tells the extension it runs in the Agents window. The `agent-sessions.code-workspace` string that [#518](https://forgejo.webgrip.dev/webgrip/unfold/pulls/518) relies on is still in the bundles; it was not re-probed at runtime.

### Plugins, marketplaces and links

The deep links (`vscode://chat-plugin/install?source=owner/repo&plugin=…`) were already in 1.143's handlers. The notes describe `owner/repo` as a GitHub repository; whether an HTTPS Forgejo URL works there is unverified. `chat.plugins.marketplaces` still accepts HTTPS `.git` URLs, so the Forgejo marketplace from [#520](https://forgejo.webgrip.dev/webgrip/unfold/pulls/520) and [#523](https://forgejo.webgrip.dev/webgrip/unfold/pulls/523) keeps working through settings. Agent plugins can now ship automation templates and canvases. Unfold's plugin could ship a template for the Copilot side, but cloud automations run on GitHub only.

### Publishing the extension

Unfold's release workflow publishes to Open VSX with `OVSX_PAT` and to the Marketplace with Entra (`MARKETPLACE_AZURE_*`) or `VSCE_PAT`. [Open VSX Trusted Publishing](https://blogs.eclipse.org/post/tamas-cservenak/trusted-publishing-open-vsx) (2026-09-30) and `vsce publish --oidc` both need GitHub Actions; GitLab support is planned for Open VSX, and Forgejo is not mentioned. If `VSCE_PAT` is set and is an Azure DevOps global PAT, it stops working on 2026-12-01. The Entra branch already exists.

### GitHub Universe 2026

- **Cloud sessions** are generally available on paid plans, with one session list across the web, Mobile, CLI, the app, VS Code, Slack and Teams; GitHub repositories only. Sandbox billing starts in November 2026, drawn from a single dollar Actions entitlement.

- **Copilot CLI** 1.0.104 and 1.0.105 add managed fusion settings and take Assisted Permissions out of experimental; in 1.0.103, ACP sessions honour saved sandbox settings.

- **Trackers.** Devin has a native Jira agent (2026-09-30); Amp takes Linear issues (2026-10-19); the Cursor Agent SDK is generally available (2026-10-20) with GitHub, GitLab and Bitbucket triggers.
- **Review.** Claude Code Review is generally available (2026-10-23, with Quick, Standard and Deep levels); Copilot approvals are generally available; Anthropic offers pooled group budgets (2026-10-28). Codex has inference residency in the EEA and Switzerland (2026-10-08).

### Does Unfold's opening still hold?

**Restated opening:** the only product where an agency runs agent work for many clients on its own EU infrastructure, across each client's own forge (Forgejo, Gitea and GitHub, with GitLab next), lets the client approve ready work, and bills per accepted ticket.

### Top five threats

1. **Copilot as the default system from ticket to merge**, bundled into GitHub Enterprise, with credit caps, AI approvals and Fusion. Agency clients on GitHub will ask why they need Unfold.
2. **VS Code as the multi-harness cockpit.** AHP 1.0, remote hosts, comparisons, and Claude and Codex on a Copilot subscription. Unfold has to win on the Work Item, budget and approval layer, not the session UI.
3. **The model labs' self-hosted runners.** "Isolated pods on your cluster" is no longer unique; sovereignty of the control plane is.
4. **Devin's forge breadth plus multi-organisation Enterprise.** The closest commercial match for mixed-forge agencies; Forgejo and price are its gaps.
5. **GitLab Duo plus JetBrains Air for the PHP agency.** Issue → merge request inside self-managed GitLab, and multi-vendor agents with governance inside PhpStorm, with no new vendor to bring in. OpenHands Enterprise is the open-source flank.

### Top five to borrow

1. Budget caps per run and per day, week or month, and the rule that an exhausted budget never removes access. A Ploeg contract question.
2. Cost per merged pull request as the headline number, the bridge to per-accepted-ticket billing ([VIK-1617](https://vikunja.webgrip.dev/tasks/1617)).
3. Named strategies for the bake-off: single, cascade and critique, with cost and time beside the judge's verdict.
4. The environment as a product object, with a runner-image smoke test, plus Claude Code's owner lock (one owner per runner, a fresh disk afterwards) for per-client isolation.
5. Copilot approvals' mechanics for client approval: scoped by path, dismissed by a new push, the verdict written in the pull request overview. And Cursor Rollouts' rule: watch after merge and open a revert pull request, never roll back alone.

### Who speaks AHP and ACP

AHP: VS Code, four open-source hosts, five clients, Microsoft SDKs in six languages, and Copilot CLI. ACP: the registry lists 52 agents, including Copilot, Cursor, Gemini CLI, Junie, Kiro CLI, Factory Droid, Goose, OpenCode, OpenHands and Mistral Vibe; Claude and Codex join through adapters. ACP clients include Zed, JetBrains AI Assistant and Air, Neovim, Emacs and Visual Studio. AHP's own guide describes the host as AHP towards clients and ACP towards agents, which is the gateway shape Unfold could use for JetBrains reach.

## Recommendations

All behaviour below is proposed. Items 1, 2, 5 and 6 are small builds; 3 is a spike; the rest need a decision or a Ploeg contract.

1. **Pin the approval-policy behaviour.** A host test that an organisation-seeded `allow-all` is honoured only where the Team placement offers it, and is refused visibly otherwise. Publish `availableApprovalModes` (read-only) so the picker shows what the Team allows. Add one line to the agency onboarding docs: `ChatDefaultConfiguration` reaches Unfold sessions.
2. **Refuse folderless sessions clearly.** A quick-chat `createSession` without a repository gets the message "Unfold works on a repository: pick one to start", never a Run and never N paid Runs. Check it once in a desktop probe, with the owner's OK, because it opens windows.
3. **Spike "hand this chat to Unfold".** Advertise `vscode.createSessionImport` behind a flag. An import becomes a proposed Work Item waiting for a person, with the turns as context, capped and scrubbed. Find the Stable menu path first; if no menu offers a remote host as an import target, stop there.
4. **Fold Keep and Undo into the per-file discard spike** (1.143 recommendation 6). Ask whether a `working-set` changeset on a remote, immutable candidate can mean "request changes: drop this file".
5. **Accept the new optional fields.** Tests that `authenticate.target` and the changeset `nonce` and `isEditing` pass through without a refusal.
6. **Check the extension in the modern UI and in the Agents window on 1.144** in the next desktop pass, which is already queued for [#518](https://forgejo.webgrip.dev/webgrip/unfold/pulls/518).
7. **Restate the market position** in [the market landscape](market-landscape.md) and [the go-to-market plan](../product/go-to-market.md) with the restated opening above, and record the consolidation (Cursor, Ona, Augment).
8. **Carry three borrowings into Ploeg contracts:** period budget caps, cost per merged pull request, and named bake-off strategies in ADR-0135 before it is accepted.
9. **Write down Copilot as a Ploeg harness through server-to-server GitHub App authentication**, as a paper spike only: licence, billing to the client's organisation, GitHub-only scope. No paid runs.
10. **Prepare for AHP 1.1.0.** When it is cut, advertise `multipleChatProviders` so Roles with different harnesses become chats of one session, and drop the subagent-chat detour if VS Code honours it.

The decisions these leave for the owner: which small builds to start (1, 2 and 5 together are about a day), whether to spike 3, whether to list Unfold on the AHP Servers list (recommended not until self-hosting is documented end to end for outsiders), whether Copilot becomes a Ploeg harness (paper spike only), and the Marketplace token before 2026-12-01 (move to the Entra secrets, or unset `VSCE_PAT` until the Marketplace listing, [VIK-1650](https://vikunja.webgrip.dev/tasks/1650), is wanted).
