# VS Code 1.143 against Unfold: surfaces a host earns by advertising, and a bake-off to mirror

Research date: 2026-10-23. This dossier follows [the 1.142 dossier](2026-10-16-vscode-1-142-fit.md) and [the surfaces crawl](2026-10-17-vscode-1-142-integration-surfaces.md) to the [1.143 release](https://code.visualstudio.com/updates/v1_143) of 2026-10-20 (1.143.1 current). It asks what 1.143 changes for Unfold's Agent Host Protocol (AHP) host and its VS Code extension, which new integrations it makes possible, and what the next release and the protocol's main branch bring.

Sources:

- the release notes in [raw markdown](https://raw.githubusercontent.com/microsoft/vscode-docs/main/release-notes/v1_143.md), the [1.144 draft](https://raw.githubusercontent.com/microsoft/vscode-docs/main/release-notes/v1_144.md) (dated 2026-10-28) and every agent page the notes link;
- `microsoft/vscode` at tags 1.142.0 (`d956e8a6`) and 1.143.0 (`2d0b7506`), and the 1.143.1 build installed on the owner's Linux machine (`e6468682`), whose `sessions.desktop.main.js` and `workbench.desktop.main.js` bundles were read for every claim about what a remote host or an extension can reach;
- the [AHP repository](https://github.com/microsoft/agent-host-protocol) on 2026-10-23, the [Agent Plugins specification](https://github.com/agentplugins/agent-plugins-spec) and its 1.1.0 working draft, and the [Copilot CLI releases](https://github.com/github/copilot-cli/releases) 1.0.100 to 1.0.103;
- this repository at `origin/development` `59df692b`, with Ploeg pinned at 0.2.0-rc.47.

**Method.** Three research agents ran in parallel: the installed bundles and the two source tags, the notes with their linked docs and the ecosystem, and a read-only map of this repository per theme. The Agents-window capability flag and the Compare Models eligibility gate were then re-read first-hand in the installed sessions bundle. Evidence read in code only is marked **(source)**. Nothing marked unverified below feeds a verdict.

**Landing.** This dossier, a dated sentence on the AHP row of the [protocol ledger](2026-09-11-ecosystem-alternatives.md#appendix-adjacent-components-and-communication-protocols), an update to [ADR 0012](../adrs/0012-agent-host-protocol-host.md), and the [watchlist](2026-10-13-protocol-integration-gaps.md#watchlist): T12, T13, T14, T17, T18 and T19 updated, T23 to T28 added. The working page the owner reviewed this from is a private artifact; this file is its durable copy.

## Verdict

1.143 breaks nothing in the host and adds four surfaces a remote host may earn by advertising a flag, one manifest line that lets the extension into the Agents window, and a trigger the watchlist was waiting for. Its headline feature, Compare Models, is built so that Unfold cannot join it and should mirror it instead.

1. **Nothing breaks.** **(source)** The client still offers AHP `1.0.0, 0.10.0, 0.9.0`, still subscribes only `ahp-root://` at connect, and the sessions-layer remote-host contribution has no diff between the tags. One new client flag, `_meta['vscode.ahpChatUris']`, changes behaviour only for hosts VS Code recognises as its own native host, which Unfold never is.
2. **One manifest line opens the Agents window to the extension.** **(source)** [#342393](https://github.com/microsoft/vscode/pull/342393) lets an extension declare `"capabilities": {"agentsWindow": {"supported": true}}`. The `agentsWindowActivation` proposal file was removed. The installed build carries the kill switch `extensions.experimental.enableAgentsWindowCapability` and still honours `extensions.supportAgentsWindow`. The docs call support "still evolving".
3. **Four host surfaces are earnable, all opt-in.** Worktree disk usage (`vscode.worktreeDiskUsage`, `vscode/measureWorktreeDiskUsage`), per-file discard on Branch, Session and Last Turn changesets (a `discard-changes` operation with scope `resource`), detached background shells with streamed output and Stop (`chat/backgroundWorkSet` with a `terminal` and three Copilot meta keys), and sandbox certificate status and commands (`vscode.sandboxCertificate.*`). A host that does not advertise them is still correct.
4. **Compare Models is one provider per comparison and judge-by-client-tools.** **(source)** Attempts and the judge all come from the provider of the current new-chat input; attempts need a session config whose `isolation` property lists `worktree`; the judge submits its verdict through two VS Code tools. Unfold's Runs cannot call VS Code tools. Mirror it: a Ploeg bake-off Shift and an Unfold scorecard with the column VS Code lacks, cost.
5. **Watchlist T17 fired.** Copilot harness sessions install plugins a trusted repository enables in `.claude/settings.json` or `.github/copilot/settings.json`; Copilot CLI 1.0.102 accepts git-subdir marketplaces from any git host. T18 did not fire: the Agent Plugins 1.1.0 draft still "defines no OAuth configuration".
6. **Chat participants are deprecated for the Copilot harness.** The extension has none and must not grow one; its road into other people's Copilot sessions is extension tools and the plugin.
7. **Policy still leaves remote hosts alone.** `vscode.temporaryAllowLocalHarness: false` prohibits Local, Claude and Codex, while remote hosts are gated only on `chat.remoteAgentHostsEnabled`. Under a Copilot-only managed profile, Unfold is the only non-Copilot host left in the Agents window.
8. **AHP main moved more than VS Code did.** Changeset nonces and `isEditing`, a per-server OAuth target, per-chat providers, source-qualified model selection, and an issue on orchestrators submitting another agent's result. None is reachable from a 1.143 client.

## What 1.143 actually is

A Copilot-harness consolidation release. The Copilot harness is the default for new sessions and runs through the Agent Host in the background. Around it:

- **Agents.** An experimental file-level working set with Keep (`chat.editor.workingSet.enabled`, editor window); Discard Changes on Branch, Session and Last Turn changesets; Compare Models (Preview, `sessions.chat.compareAgents.enabled`); tab shortcuts in an empty side pane; the Session Activity Bar (`sessions.showSessionActivityBar`); find and create files from the empty Files tab; chat history restored in slices; worktree cleanup (`Chat: Open Worktree Cleanup`, `chat.agentSessions.sessionStorageCleanupSuggestion.enabled`).
- **Models.** On-device MAI Code 1.1 Flash through llama.cpp (`chat.copilot.localModel.*`, GitHub sign-in, 96 GB of GPU memory); bring-your-own OpenAI model for Voice Mode.
- **Sandboxing.** `Sandbox: Manage Trusted CA` for the sandbox credential proxy's certificate authority, "local or remote" hosts; a per-session "Sandboxing for terminal" toggle where policy allows bypass.
- **Chat.** Canvases from the New Chat menu (still Copilot-local); output and Stop for detached background shells.
- **Source control.** A file list beside the multi-file diff editor (`multiDiffEditor.experimental.fileList`).
- **Enterprise.** `telemetry.headersProvider` for Copilot Agent Host sessions; managed model defaults (`model`, `autoTier`); "Why Local is disabled" with `vscode.temporaryAllowLocalHarness` and `vscode.temporaryDefaultToLocalHarness`; fewer approval prompts for managed tools; managed plugins install automatically; Claude and Codex sessions stay listed under policy and can be continued in Copilot.
- **Setup.** The installers offer Copilot CLI (`chat.copilotCliCommand.enabled`, policy `CopilotCliCommand`).
- **Deprecated:** none in the notes. Outside the notes, the docs release of 2026-10-20 deprecates [chat participants](https://code.visualstudio.com/api/extension-guides/ai/chat) for the Copilot harness.

The notes carry no extension-authoring section. **(source)** `vscode.d.ts` is byte-identical between the tags. Proposals added: `languageModelRateLimit`, `autoClosingPairBeforeText`; changed: `speech` (voice live sessions), `timeline` (reworked), `externalUriOpener`; removed: `agentsWindowActivation`. URL-opening hooks ([#109277](https://github.com/microsoft/vscode/issues/109277)) and contributable chat context ([#271104](https://github.com/microsoft/vscode/issues/271104)) moved to the 1.144.0 milestone.

### The agent host client, changed in source

- **Versions and subscriptions.** `PROTOCOL_VERSION` is `'1.1.0'`, the baselines `['1.0.0', '0.9.0']`, the private `0.10.0` kept; `initialSubscriptions` is `[ahp-root://]`. Unchanged.
- **Client meta.** `vscode.ahpSessionUris: true` and, new, `vscode.ahpChatUris: true`. A new `agentHostOlderHostCompatibility.ts` derives legacy chat URIs only for native hosts.
- **Extension requests added** (`agentHostExtensionProtocol.ts`): `vscode/measureWorktreeDiskUsage {uri, requestId}` → `{sizeBytes?}`, `vscode/cancelWorktreeDiskUsage`, `vscode/readSavedChat`, `vscode/completeSavedChatContinuation`, `vscode/moveSession` (now defined here), and in `sandboxCertificateProtocol.ts` `vscode/installSandboxCertificate`, `rotateSandboxCertificate`, `removeSandboxCertificate`. Each is sent only when the host's initialize result advertises the matching meta: `vscode.worktreeDiskUsage`, `vscode.readSavedChat`, `vscode.completeSavedChatContinuation`, `vscode.sandboxCertificate.install|rotate|remove`, `vscode.sessionMove`. Unfold advertises none, so none is sent.
- **Registry.** `chat/configChanged`, `channel/frame`, `channel/credit`, `channel/snapshot`, `tcp/data`, `tcp/eof`, `tcp/reset` are registered as 1.1.0 and filtered by the negotiated version, so none is reachable.
- **Canvas gate.** `supportsCanvasPresentation` is set only for the local `copilotcli` provider; the remote provider's adapter options never set it.
- **MCP forwarding.** `agentHostMcpServerSupport.ts` has no diff; forwarded definitions still drop `oauth`.
- **Policy.** `remoteAgentHost.contribution.ts` in the sessions layer has no diff. New device policy `CopilotCliCommand`; `CopilotOtelEnabled` is now enforced; managed `permissions.limitTo` is accepted. Claude and Codex chats under policy are continued in Copilot by copying them through `vscode/readSavedChat` and `vscode/completeSavedChatContinuation`, both gated on host meta.

### AHP after 1.0.0

No release since 2026-10-02. On main: `chat/configChanged` with `chatMutable` config, windowed delivery and the TCP channel are registered as 1.1.0. Merged without a bump: steering as `PendingMessage.kind` in `queuedMessages` ([#512](https://github.com/microsoft/agent-host-protocol/pull/512), which the host already tolerates), `createChat.title` ([#526](https://github.com/microsoft/agent-host-protocol/pull/526)), `AuthenticateParams.target` for one MCP server in one session ([#535](https://github.com/microsoft/agent-host-protocol/pull/535)), `ChangesetFile.nonce` and `ChangesetOperationTarget.nonce` ([#539](https://github.com/microsoft/agent-host-protocol/pull/539)), `ChangesetFile.isEditing` ([#540](https://github.com/microsoft/agent-host-protocol/pull/540)). Open and relevant: per-chat `provider` ([#534](https://github.com/microsoft/agent-host-protocol/pull/534)), source-qualified model selection ([#543](https://github.com/microsoft/agent-host-protocol/pull/543)), tool-call timing ([#465](https://github.com/microsoft/agent-host-protocol/pull/465)), and authorized non-user message submission ([#542](https://github.com/microsoft/agent-host-protocol/issues/542)). Still draft: replay cursors [#494](https://github.com/microsoft/agent-host-protocol/pull/494), session artifacts [#508](https://github.com/microsoft/agent-host-protocol/pull/508), canvas registry [#528](https://github.com/microsoft/agent-host-protocol/pull/528), windowed-delivery clients [#529](https://github.com/microsoft/agent-host-protocol/pull/529). The maintainer declined to maintain a TypeScript server SDK ([#422](https://github.com/microsoft/agent-host-protocol/issues/422)) in favour of the community `@ahpd/server`. The README lists an AHP-ACP Gateway since 2026-10-16; no JetBrains, Zed or Cursor AHP client exists, both remain on ACP.

## Deep dives

### The extension inside the Agents window

`apps/unfold/extensions/vscode/package.json` declares no capabilities and no API proposals and keeps `engines.vscode ^1.99.0`. Because extensions were off in the Agents window, [#419](https://forgejo.webgrip.dev/webgrip/unfold/pulls/419) routes Work Item links through the editor window by `windowId`, and the README does not mention the `extensions.supportAgentsWindow` opt-in. Older VS Code ignores unknown manifest keys, so the capability block costs nothing. Three questions decide what follows: do the Unfold views, the Work Item webview and the `unfold.*` commands exist inside the Agents window; does a plain `vscode://webgrip.unfold/work-item` link resolve there; which activation events fire. If the panel opens, the chat's "Open the Work Item in VS Code" line can drop the `windowId` detour for 1.143 clients.

### The Unfold Agent Plugin

**(source)** Per workspace folder the sessions bundle reads `.claude/settings.json`, `.claude/settings.local.json`, `.github/copilot/settings.json` and `.github/copilot/settings.local.json`, keys `enabledPlugins` and `extraKnownMarketplaces`; Claude values win when both name a plugin; nothing is recommended before workspace trust ([#341618](https://github.com/microsoft/vscode/issues/341618)). Precedence is managed settings, trusted repository, then the person; auto-installed plugins are enabled for the session only. `chat.plugins.marketplaces` accepts `owner/repo#ref`, an HTTPS `.git` URL, SCP syntax and `file:///`, so a Forgejo-hosted marketplace works; only Team assignment is GitHub-only.

What exists: a Claude Code plugin at [`extensions/claude-code`](../../extensions/claude-code/) (0.2.0: hooks, agent trace, the `link-work-item` skill) with a marketplace at the repository root, per [ADR 0047](../adrs/0047-people-link-their-own-agent-sessions-through-a-plugin-agent-trace-and-telemetry-never-a-claude-sign-in.md). No root `plugin.json` on the Agent Plugins 1.0.0 schema, no `mcp.json`, no `enabledPlugins` anywhere. The host refuses plugins VS Code pushes ([`customizations.ts`](../../src/ahp/customizations.ts)), which stays right: Runs get skills from Ploeg's catalogue, not from a person's editor.

Still blocked: the 1.1.0 draft's `mcp.json` carries type, URL and non-secret headers only, so the `ploeg-mcp` client id is supplied by the extension or a one-time sign-in, as [#383](https://forgejo.webgrip.dev/webgrip/unfold/pulls/383) does. New docs of 2026-10-22 say the Copilot harness cannot forward `${input}` or SecretStorage secrets into HTTP MCP headers.

### Compare Models, read in the bundle

**(source)** The comparison is offered when the active session's provider lists session types with `supportsWorktreeConfiguration` (true for every agent synced from an AHP root state, "isolation is host-owned"), the session's config schema has an `isolation` property whose enum includes `worktree`, the selected folder is one of the session's workspace folders and passes a Git repository-with-remote check, and a comparison branch resolves. Every attempt and the judge take the provider id of the current new-chat input and models from that provider's catalogue, and run with `isolationMode: 'worktree'` and Allow all. The judge starts when at least two attempts finished and one succeeded, in a background session titled "Judge: …", and is told to call `#readAttemptComparison` once and `#completeAttemptComparison` with recommended attempt, rationale, conflicts and per-attempt notes; those are VS Code tools. Results live in profile storage (`sessions.comparisons`). Synthesize needs a judge and a synthesizer model and starts only on click. The scorecard shows time and tokens and no cost.

Unfold's session config ([`session-config.ts`](../../src/ahp/session-config.ts)) has `repository, team, budgetUsd, placement, approvalMode, title` and no `isolation`; its Runs execute in Ploeg pods and cannot call VS Code tools. Structurally eligible as attempts after adding an isolation property, never as judge. Joining would multiply paid Runs behind a button that shows no cost.

What already is a bake-off, in pieces: Ploeg [ADR 0098](../../../ploeg/docs/adrs/0098-an-operator-admission-may-choose-each-runs-harness-from-its-teams-allowlist.md) and [ADR 0103](../../../ploeg/docs/adrs/0103-an-operator-admission-may-choose-each-runs-model-from-the-models-its-roles-policy-lists.md) (an admission names a harness and a model), [ADR 0096](../../../ploeg/docs/adrs/0096-a-shadow-reader-records-its-verdict-and-never-acts.md) (a shadow Role records a verdict and never acts), Unfold [ADR 0046](../adrs/0046-a-running-runs-health-is-computed-from-its-own-facts-and-a-judge-only-advises.md) (the run health judge), cost and tokens per Run in the operator API, and the model plan's open question of cost per accepted pull request per model ([VIK-1617](https://vikunja.webgrip.dev/tasks/1617)). Nothing in `src/` posts to the operator admission yet; [ADR 0044](../adrs/0044-sessions-run-in-ploeg-with-a-harness-chosen-per-session-and-interaction-kept.md) plans the picker.

### Workspace storage

**(source)** The cleanup editor lists sessions whose workspace folders carry `gitRepository.workTreeUri`, sizes them through `vscode/measureWorktreeDiskUsage`, protects active, running, needs-input and pinned sessions, and cleans by `archiveSession`; bundle thresholds are 5 GB, 20 worktrees and 15 days. Without the host meta it logs "host does not support aggregate measurement" and nothing is eligible. Ploeg keeps a paused Run's pod for a bounded time ([ADR 0101](../../../ploeg/docs/adrs/0101-a-paused-run-keeps-its-pod-and-session-for-a-bounded-time-and-is-never-retried-automatically.md)); Unfold's own runtime retains workspace volumes after disposal with no retention rule, and the extension's [`checkout.ts`](../../extensions/vscode/src/checkout.ts) adds local worktrees and never removes them. The host already maps VS Code's archive to done.

**Read again on 2026-10-23 before building.** **(source)** VS Code gives a remote session a `workTreeUri` only when its summary names a `project` and its first `workingDirectories` entry differs from the project's URI (`buildAgentHostSessionWorkspace`); the `.worktrees` path rule applies to archived sessions only. The host sends a `project` and no `workingDirectories`, so adding one would move the Files tab, terminals and folder picker to a new working directory just to earn a size. The cleanup editor then tells the person it deletes the worktree, while VS Code only archives the session and Unfold keeps the volume. And Unfold ADR 0044 moves execution into `ploeg-worker`, whose workspaces end 60 seconds after a Run (`executor.sandbox.ttlSecondsAfterFinished`) or at the pause bound, so the volumes this would measure are going away.

### Review

**(source)** Discard is an AHP changeset operation the client renders when a host advertises `{id: "discard-changes", scopes: ["resource", …]}`; the 1.143 change is VS Code's own node host offering it on more changeset kinds ([#341609](https://github.com/microsoft/vscode/pull/341609), [#342035](https://github.com/microsoft/vscode/pull/342035), [#342260](https://github.com/microsoft/vscode/pull/342260)). The client's changeset kinds are `branch`, `session`, `turn`, `uncommitted`. The multi-diff file list is bound on unconditionally inside every multi-diff editor. [`review.ts`](../../src/ahp/review.ts) serves accept, reject, request-changes and accept-and-open-pull-request as changeset operations, echoes `changeset/filesReviewChanged` without storing it, and works on the whole candidate. The loudest complaint about the Copilot harness, losing per-change Keep and Undo ([#339363](https://github.com/microsoft/vscode/issues/339363)), gets a file-level Keep in 1.143 that is experimental, Copilot-only and editor-only.

### Background shells

**(source)** The Background Shells pill has no provider gate. The reducer upserts `chat/backgroundWorkSet` entries by id; the projection shows `kind: "shell"` entries, marks `_meta["vscode.copilot.shellAttachment"] === "detached"` as Detached, reads output only when `terminal` names a terminal resource the client can subscribe to (`content[]`, `lifecycle.status`, `exitCode`), and shows Stop only with `_meta["vscode.stopBackgroundWork"] === true`, then sends `vscode/stopBackgroundWork {chat, id}` and expects `{stopped}`. [`terminals.ts`](../../src/ahp/terminals.ts) already serves a Run's commands as read-only terminals; [`host.ts`](../../src/ahp/host.ts) answers Stop with `{stopped: false}` and never emits `chat/backgroundWorkSet`. [RFC-0006](../../../../docs/design/rfc-0006-live-command-output.md) phase 2 is the prerequisite.

### Sandboxing, telemetry and policy

The Copilot runtime's credential proxy hands tools placeholder credentials and substitutes real ones at approved destinations, the idea Ploeg's ADR 0034 holds; its CA trust is an OS-level concern that Ploeg's ADR 0037 egress proxy avoids by pushing the bundle into the pod. The per-session "Sandboxing for terminal" toggle and the remembered approvals of assisted permissions map onto Ploeg [ADR 0106](../../../ploeg/docs/adrs/0106-a-run-declares-an-isolation-floor-and-a-cell-runs-it-at-the-strictest-class-it-can-honour.md) and [ADR 0100](../../../ploeg/docs/adrs/0100-an-attended-run-relays-its-harnesss-requests-through-ploegd-and-falls-back-to-its-teams-policy.md). `telemetry.headersProvider` has zero hits in the VS Code client and lives in the Copilot runtime; the idea, short-lived collector headers from a helper, fits Ploeg [ADR 0113](../../../ploeg/docs/adrs/0113-a-runs-harness-exports-opentelemetry-to-a-collector-set-per-team-and-role.md). Managed model defaults and the Team manifest of Ploeg [ADR 0110](../../../ploeg/docs/adrs/0110-a-team-is-ploegs-own-manifest-of-charter-crew-permissions-intake-and-skills.md) answer the same question: which default applies and who set it. On policy, the 1.142 dossier's recommendation 7 is answered for 1.143: the risk is absent, and the trend says a remote-host policy is likely.

### On-device models

MAI Code 1.1 Flash runs through llama.cpp on the person's machine with GitHub sign-in and 96 GB of GPU memory, for no credits. Ploeg's zero-credit lane is Hetzner's Qwen behind LiteLLM for the judge and the decider. Nothing to adopt.

## Recommendations

Items 1, 2 and 4 are buildable now, 3 is a rule to write, and 5 to 8 need a decision or a Ploeg contract first. On 2026-10-23 items 1 and 2 were built as [#518](https://forgejo.webgrip.dev/webgrip/unfold/pulls/518) and [#520](https://forgejo.webgrip.dev/webgrip/unfold/pulls/520), the read-only tools of item 1 as [#521](https://forgejo.webgrip.dev/webgrip/unfold/pulls/521), and the Ploeg half of item 5 was proposed as [ploeg-hq#220](https://github.com/ploeg-hq/ploeg/pull/220). All behaviour below is proposed.

1. **Declare the Agents-window capability and test it in the desktop pass ([VIK-1922](https://vikunja.webgrip.dev/tasks/1922)).** Answer the three questions above, document both opt-in paths in the README, and decide whether [#419](https://forgejo.webgrip.dev/webgrip/unfold/pulls/419)'s `windowId` routing stays for 1.142 only. Never add a chat participant; the next step toward Copilot sessions is read-only tools through `vscode.lm.registerTool`, feature-detected so the engine floor stays.
2. **Make the Claude Code plugin a spec-conformant Agent Plugin.** Root `plugin.json` on the 1.0.0 schema, `skills/`, an `mcp.json` naming `ploeg-mcp` and the remote `unfold-mcp` by URL, the Claude hooks under the reverse-domain folder, a `marketplace.json` on Forgejo pinned by SHA, and three install paths documented. Then offer connected repositories a `.claude/settings.json` snippet with `enabledPlugins` and `extraKnownMarketplaces`, first as text to copy, later through the connect flow ([VIK-2245](https://vikunja.webgrip.dev/tasks/2245)). Amend ADR 0047 rather than add a sibling.
3. **Do not advertise worktree disk usage; write the retention rule instead.** Measuring sizes needs a `workingDirectories` change that moves the session's folder, and the cleanup it feeds only archives while saying it deletes, as the workspace storage dive records. The storage problem that exists today is Unfold's own: workspace volumes kept after disposal with no retention, and local worktrees the extension never removes. Write that rule (never a running, paused, needs-you or pinned session; candidates kept until the pull request merges or closes plus a grace period; sizes on the fleet view) and revisit the VS Code side only if workspaces outlive ADR 0044.
4. **Publish a Run's long-running commands as detached background shells.** Emit `chat/backgroundWorkSet` on the existing `ahp-terminal:` channel with the three meta keys, remove it on exit, and answer Stop by asking whether to withdraw the Run, as the Work Item's Stop does, with `{stopped: false}` and a visible reply while the question waits. Amend RFC-0006 first. ADR-0008's preview environment fits the same slot.
5. **Mirror Compare Models as a Ploeg bake-off.** Ploeg side, a contract with no consumer words: one Work Item admitted N times under one reserved budget, each admission naming a model, harness and effort; one shadow judge Role that reads all outcome reports and records a verdict with a recommended Run; the person picks the winner; the others expire after the walkthrough. Unfold side, a scorecard per attempt (model, harness, wall time, tokens, settled cost, the judge's note, open candidate), Synthesize as a Round on the recommended candidate, and the cost stated before a bake-off starts. The owner chose to propose the Ploeg ADR now; the ADR is drafted in ploeg-hq alongside this dossier.
