# De Vloer — social and profile copy

The canonical text for every profile and listing outside the repository. One source, so the
description does not drift per platform. Claims follow what the product actually does today:
the demonstration makes zero model calls, live integrations carry the limits in
[validation.md](../validation.md), and nothing here promises a hosted service.

## Descriptions

### Short (directories, integration lists)

> De Vloer is the human workbench beside Ploeg: durable operator sessions, isolated agent
> workspaces, interchangeable harnesses, and evidence people can review. Apache-2.0.

### Medium (repository description, package listings)

> De Vloer is a self-hosted workbench for people steering remote agent crews. Bring a task
> from Vikunja, ClickUp, Forgejo, GitHub or GitLab, choose a reusable crew and a spending
> limit, and supervise the work from a browser or VS Code.
>
> The tracker owns priorities, Ploeg owns unattended dispatch, and De Vloer owns interactive
> sessions and human intervention. Agents run on your configured server, never on the laptop
> you steer from. Candidates come back as an inspectable patch with a manifest and signed
> provenance, and a person decides what gets published.

### Long (about pages, write-ups)

> De Vloer is the human workplace in an agent estate — the shop floor, which is what its name
> means in Dutch. It does not do the work: it carries it, and gives a person somewhere to
> stand while they watch.
>
> An operator brings a task in from the tracker the team already uses, picks a crew and a
> budget, and starts a session. The agents run in an isolated workspace on a configured
> server — a hardened container, a Kubernetes pod, or a plain working directory for trusted
> development — reachable from a browser or the VS Code extension. Sessions are durable and
> replayable: pause, resume, cancel, answer a permission request, read the evidence.
>
> What comes back is a candidate, not a merge: a binary-capable patch, a self-contained
> snapshot, a manifest, and in-toto provenance. Independent checks run outside the agent's
> own workspace, and publication stays a human decision. The application has zero
> third-party npm runtime dependencies and is Apache-2.0.

**Note:** De Vloer is pre-1.0. Read [validation.md](../validation.md) before describing any
integration as production-tested.

## Naming

- The product is **De Vloer**, capitalised, both words. Not "de vloer", not "DeVloer", not "Vloer"
  on first mention. `Vloer` alone is fine as shorthand once the full name has been used, and is
  how the domain documents refer to it beside Ploeg.
- The repository is `de-vloer`. The mark and the name are trademarks — see [TRADEMARK.md](TRADEMARK.md).
