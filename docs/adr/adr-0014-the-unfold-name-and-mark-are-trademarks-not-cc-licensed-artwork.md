# The Unfold name and mark are trademarks under a usage policy, not CC-licensed artwork

## Context and Problem Statement

[ADR-0013](adr-0013-the-product-is-named-unfold.md) named the product Unfold, and `docs/brand/` now holds its identity: the Vouwvlieger mark, an outlined wordmark, lockups and colour tokens, generated by `scripts/build-brand.mjs`. The repository is Apache-2.0, which answers copyright for those files. It does not answer whether a fork may ship as Unfold, or whether a vendor may use the mark in a way that implies endorsement.

Ploeg and Vloer answered the same question for their own marks ([Ploeg ADR-0022](../../apps/ploeg/docs/adrs/0022-the-name-and-mark-are-trademarks-not-cc-licensed-artwork.md), [Vloer ADR-0020](../../apps/unfold/docs/adrs/0020-the-name-and-mark-are-trademarks.md)). This record gives the product's mark the same answer. It stays proposed until a trademark search is done: Squarespace lists "Unfold", its social-media app, among its trademarks, and classes 9 and 42 need a lawyer's check before Unfold is sold.

## Decision Drivers

* A Creative Commons licence is irrevocable. A policy file can be tightened, loosened or withdrawn if the search turns up a conflict or the project changes steward.
* Creative Commons itself warns that applying its licences to a trademark can cost the trademark rights.
* The harm to prevent is misattribution, a fork or vendor passing itself off as Unfold, not copying. Trademark addresses that; copyright does not.
* Apache-2.0 §6 already withholds trademark rights, so the code licence and a trademark policy compose without a second copyright answer.
* The product and its parts should follow one rule, so a reader who knows Ploeg's or Vloer's policy knows Unfold's.

## Considered Options

* Name and mark reserved as trademarks under a usage policy; the artwork files stay under the repository's Apache-2.0
* CC BY 4.0 on the artwork files
* CC BY-ND 4.0 on the artwork files
* All rights reserved on the artwork files

## Decision Outcome

Chosen option: "Name and mark reserved as trademarks under a usage policy", because it protects what matters, that Unfold and the mark mean this project, without an irrevocable grant to modify the mark, and it matches Ploeg and Vloer.

* [`docs/brand/TRADEMARK.md`](../brand/TRADEMARK.md) is the policy. It allows nominative use without asking: reproducing the unmodified mark to refer to Unfold, linking, reporting, and stating compatibility. It withholds shipping a modified or forked distribution under the name or mark, and any use implying endorsement, affiliation or certification.
* No `LICENSE` or `COPYING` file goes under `docs/brand/`. The files are Apache-2.0 like the rest of the repository; §6 keeps the mark out of the grant.
* Archivo stays under its own SIL OFL 1.1 and is not Unfold's to license.
* While this record is proposed, the policy says so at its top and claims no registered right.

### Consequences

* Good, because badges, write-ups and integration lists need no permission.
* Good, because it is reversible: if the search finds a conflict, the policy and the name can change without a CC grant left behind.
* Good, because the repository keeps a single copyright answer.
* Bad, because an unregistered mark rests on weaker, territorial rights, and the Squarespace listing may limit even those. The trademark search decides whether to register, rename or accept the risk.
* Bad, because enforcement is manual.

### Confirmation

`mise run brand-check` (`node scripts/build-brand.mjs --check`), run by `mise run verify` in its `brand` group, fails when `docs/brand/TRADEMARK.md` is missing, when a `LICENSE` or `COPYING` file appears under `docs/brand/`, or when the root `README.md` stops linking the policy.

## Pros and Cons of the Options

### CC BY 4.0 on the artwork files

* Good, because it is a common answer for project artwork.
* Bad, because it is irrevocable and grants the right to modify the mark, which Creative Commons warns can dilute it.

### CC BY-ND 4.0 on the artwork files

* Good, because "no derivatives" is closer to what a mark needs.
* Bad, because it also blocks legitimate adaptation such as a monochrome print or a platform icon size, and it is still irrevocable.

### All rights reserved on the artwork files

* Good, because it is the most protective.
* Bad, because it makes ordinary reference legally uncertain and conflicts with the repository-wide Apache-2.0 unless carved out, adding a second copyright answer.
