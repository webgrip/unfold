# Hive × Unfold: fit record

Date: 27 October 2026, against `origin/development` at `8ec1854e`, with Ploeg pinned at `0.2.0-rc.81` (the seam map read the `0.2.0-rc.64` bundle; the Ploeg claims this record leans on were re-checked against rc.81), and Hive `v5.186.4` (released 18 October; `v5` head `3f307bb`). This is a record. It changes no decision by itself. The [glossary](../reference/glossary.md) defines each capitalised term.

> **Method.** Four research agents ran in parallel: a crawl of hive.hivecommons.dev, hivecommons.dev and the repository's documentation ([1-docs-crawl.md](evidence/2026-10-27-hive/1-docs-crawl.md)); a source dig over a read-only full-history clone and the GitHub API ([2-repo-dig.md](evidence/2026-10-27-hive/2-repo-dig.md)); an ecosystem and absence sweep ([3-ecosystem-and-absences.md](evidence/2026-10-27-hive/3-ecosystem-and-absences.md)); and a read-only seam map of this repository ([4-seam-map.md](evidence/2026-10-27-hive/4-seam-map.md)). Downloaded pages and code were treated as data, never run. These claims were checked first-hand rather than taken from an agent: the GitHub numbers (77 stars, 47 forks, created 17 April 2026, default branch `v5`, latest release `v5.186.4`); the CNCF project page stating Hive Commons was "accepted to CNCF on September 29, 2026" at Sandbox level; the README's outcome cards and the [outcome benchmark](https://github.com/hivecommons/hive/blob/v5/src/docs/benchmarks/outcomes-2026-10.md); the [security model](https://github.com/hivecommons/hive/blob/v5/src/docs/security-model.md) control inventory, including that the credential-free sandbox is opt-in; `getting-started.md` stating that GitLab, Gitea and Forgejo are "not supported for running a hive"; the budget in `src/pkg/governor/governor.go` suppressing kicks rather than capping a run; and, on the Ploeg side, that `pkg/worker/pushfence.go` fences ref updates to the Run branch only, with no path rule.

## Verdict

**Hive is the closest product to Unfold and Ploeg surveyed so far, and still not a dependency or a substitute. Do not run Unfold's work on it. Mine six of its designs, add it and Fullsend to the competitor ledger, and watch three named triggers that would close the gap.**

Hive is "an operations plane for fleets of AI agents" for GitHub repositories: one Go binary in one container that reads issues and pull requests, kicks long-lived agent CLIs in tmux sessions, gates their work with an AI review swarm plus CI, and merges on green once a repository has earned the highest of six autonomy levels. It overlaps Ploeg's dispatch, review and fix loop almost one to one. It differs on exactly the properties Ploeg exists for: GitHub is the only forge that runs, money is counted after the fact and only stops new kicks, the agent holds its own scoped GitHub token unless an opt-in sandbox is turned on, and there is no tenant boundary.

The two verdict axes, stated separately:

- **Maturity** is high in volume and narrow in people. Hive has 9,836 pull requests (9,179 merged), 10,633 commits and 567 releases between 27 August and 18 October, about eleven a day. One person, Andy Anderson of IBM Research, wrote 69,4 % of all commits; the top four identities wrote 90,8 %. Its own bots authored 19,2 % of its pull requests. It is a CNCF Sandbox project as of 29 September 2026, with the contribution agreement still unsigned. Three of five maintainers work at IBM. Every adopter is run by, or one step from, a maintainer.
- **Fit** decides. Hive is a GitHub-only, single-organisation, self-hosted control plane with its own dashboard, scheduler and work ledger. Adopting it would mean replacing Ploeg, not plugging into it, and giving up Forgejo, admission before spend and the credential-free harness by default.

**Absences.** Across Hive's code, documentation and website there are zero mentions of Vikunja, ClickUp, KEDA, OpenBao, AHP, Omnigraph, Unfold or Ploeg. Forgejo, Gitea and GitLab have adapters in `pkg/forge` but are "Planned" for running a hive ([#14096](https://github.com/hivecommons/hive/issues/14096)). Kata and gVisor appear only as an optional runtime-class name. ACP is used only to ask Goose for its model list. In this repository, Hive, `hivecommons` and Spektacular had zero mentions, and so did **Fullsend**, which Hive itself calls "the closest open-source comparison" and which already supports GitHub, GitLab and Forgejo.

Summary:

1. **What it is.** A co-maintainer system: deterministic Go before the model, AI review and CI after it, one autonomy dial (`acmm_level`, L1–L6) that decides which agents run in which mode ([section 1](#1-what-hive-is)).
2. **Autonomy is one dial.** Advisory, Measured, Holdgated and Full modes are minted per level; "merge permission is not minted below L6". Ploeg has the knobs but no dial; the Team manifest that would hold one ([ADR-0110](../../apps/ploeg/docs/adrs/0110-a-team-is-ploegs-own-manifest-of-charter-crew-permissions-intake-and-skills.md)) is proposed and not built ([1.2](#12-autonomy-the-acmm-dial)).
3. **Money is visibility, not admission.** Spend is a list-price estimate from session logs; a weekly budget stops new kicks. The only hard dollar cap is US$ 25 a day on the Claude Managed Agents path. Ploeg authorizes a budget before a Run starts and settles after it ([1.4](#14-money)).
4. **Credentials.** By default each agent can read a mode-scoped GitHub App token; pull-request creation and merge go through relays Hive runs as the App. A credential-free sandbox with a push broker exists and is opt-in behind two switches ([1.5](#15-isolation-and-credentials)).
5. **Hive publishes outcome numbers.** About US$ 2,13 per merged pull request over 2,869 merges, with Wilson intervals and minimum bases. Unfold's only comparable figure is US$ 1,04 per merged bronze Work Item over 3 merges ([section 5](#5-design-worth-mining)).
6. **Where it competes.** For a GitHub-only open-source maintainer, Hive is free, Apache-2.0 and CNCF-badged. For an agency on Forgejo or GitLab that must keep spend, credentials and client repositories apart, it does not run today ([section 4](#4-where-it-competes-and-where-it-does-not)).

## 1. What Hive is

### 1.1 Self-description and surfaces

- README: "Every team has one: the maintainer who reads every pull request, never lets red merge, and sends work back in one line. Hive puts that person between your coding agents and your main branch." And: "Hive is like a CI system, except the job is an AI coding agent and the gate is an AI review plus your existing CI." ([README](https://github.com/hivecommons/hive/blob/v5/README.md))
- Landing page: "a co-maintainer system for your GitHub projects: AI agents (Claude, Copilot, Codex, Antigravity, Goose) do the chores. You decide how much they may do." ([hive.hivecommons.dev](https://hive.hivecommons.dev/))
- Landscape page: "an operations plane for fleets of AI agents" ([landscape.md](https://github.com/hivecommons/hive/blob/v5/src/docs/landscape.md), dated 23 October 2026).
- Process model: one container. `entrypoint.sh` is PID 1 and supervises a Node proxy (:3001, the dashboard front door), the Go `hive` binary (:3002) and ttyd (:7681, a web terminal onto agent sessions). Inside the binary run the governor loop, the agent manager, the dashboard API, a MITM GitHub proxy (:18443) and an inference translator (:18444) ([architecture.md](https://github.com/hivecommons/hive/blob/v5/src/docs/architecture.md)).
- Agents are long-lived tmux sessions, one per role (scanner, reviewer, quality, ci-maintainer, sec-check, architect, outreach and others), optionally under per-agent Unix users. A "kick" is a work order typed into the agent CLI's prompt (`src/crux/agent/manager_kick.go:103`).
- The governor is a queue-depth scheduler: each tick it enumerates actionable issues and pull requests, picks a mode from the queue depth and kicks agents whose cadence is due.
- Surfaces: a 3,9 MB single-file dashboard with SSE, a terminal UI (`hivectl`), a Discord bot, ntfy/Slack/Discord alerts, and a hub at hive.hivecommons.dev that registers hives ("spokes"), runs leaderboards and offers a free, admin-approved, best-effort hosted service. "Hosted is the funnel, self-hosted is the destination." No pricing exists anywhere.
- Work sources: GitHub Issues, GitHub Projects, Linear, Jira Cloud and Data Center. Agent backends in tiers: T1 claude, litellm, copilot, codex, goose; T2 muse, opencode; T3 aider, kilo, openhands and others. Inference gateways: vLLM, llm-d, LiteLLM, watsonx.ai, OpenRouter, any OpenAI-compatible endpoint. Backends are a `switch backend` in `src/crux/agent/manager_launch.go:915`, not an interface.

### 1.2 Autonomy: the ACMM dial

ACMM is the "AI Codebase Maturity Model", from a single-author IBM Research paper ([arXiv 2604.09388](https://arxiv.org/abs/2604.09388)) for which Hive is the reference implementation. The model itself is assessed in the [maturity model fit record](2026-10-27-ai-codebase-maturity-model-fit.md), and [ADR-0047](../adr/adr-0047-unfold-describes-a-repository-with-the-ai-codebase-maturity-model-and-delivers-at-level-5.md) proposes adopting its levels without Level 6. The dial is the top-level key `acmm_level` ([acmm-policy-matrix.md](https://github.com/hivecommons/hive/blob/v5/src/docs/acmm-policy-matrix.md)):

| Level | Name | What agents may do |
|---|---|---|
| L1 | Inception | Advisory notes only |
| L2 | Advisory | Findings on the dashboard; the reviewer posts comment-only reviews |
| L3 | Quality-Gated | The quality agent opens hold-gated pull requests |
| L4 | Security-Aware | Delivery agents open issues; quality, sec-check and ci-maintainer open hold-gated pull requests |
| L5 | Semi-Autonomous | Every pull request carries `hold`; a person lifts it |
| L6 | Autonomous | Merge on green CI |

Each level maps each agent to one of four modes (Advisory, Measured, Holdgated, Full), and the mode picks the tier of GitHub App token the agent receives and the method/path table the proxy enforces. Hive admits that the L5 `hold` label "is applied by agent policy"; the real guarantee is that "merge permission is not minted below L6". Per-repository levels were declined; per-repository controls are pause, `auto_merge: false` and `self_authorization_hold`.

### 1.3 Lifecycle and the people in it

- One label family, `stage/NNN-*`, written only by a central stage engine (Hive ADR-0025). Issues move through `010` actionable, `020` claimed, `030` pr-in-progress, `045` needs-decision; pull requests through `050` review-pending, `060` reviewed, `070` fixing, `085` needs-decision, `090` ready-for-human-merge, `095` pre-merge-soak, `100` merge-queue.
- A person answers on the forge itself: `/hive approve` or `/hive decision <text>` on the issue or pull request (write access required, swept about every five minutes). A `requires_human` review verdict clears only with a GitHub Approve review on the current head.
- Review is a swarm of perspectives with verdicts recorded per head; a "delta re-review" judges only what changed since the last judged head ([#14622](https://github.com/hivecommons/hive/pull/14622)). An escalation circuit breaker adds `needs-human` after repeated fix loops.
- Guards with no Ploeg equivalent: a **workflow-path fence** that blocks agent changes to `.github/workflows/**` and `.github/actions/**` until an owner approves the current head ([#14672](https://github.com/hivecommons/hive/pull/14672)); a **self-authorization hold** on pull requests whose only rationale is an issue Hive itself filed; a **hold guard** that catches drift after approval; **trajectory review** for goal drift; **intent verification** for scope creep; and **ioscan**, which screens issue and file text for prompt injection before an agent reads it, with canaries.

### 1.4 Money

- `governor.budget.{total_tokens, usd, period_days=7, critical_pct=90, coins}`. When the weekly total is used, the governor stops new kicks (`src/pkg/governor/governor.go`). There is no cap per run and nothing is checked before spend.
- Cost is "a list-price estimate, not a billing feed": a token collector scans each backend's session logs. The dashboard's cost-by-work-item panel says "This is visibility only: nothing here gates or budgets a kick".
- The one hard cap: `daily_budget_cents: 2500` on the Claude Managed Agents path.
- Compare [Ploeg ADR-0012](../../apps/ploeg/docs/adrs/0012-two-level-budgets-authorized-and-settled.md): at claim, ploegd authorizes `min(roleCap, pool − spent − reserved)`, and each Run gets a LiteLLM key with that `max_budget`.

### 1.5 Isolation and credentials

- Default path: one container, agents as tmux sessions under per-agent Unix users. All outbound HTTPS is forced through the MITM proxy by iptables, which inspects only `api.github.com` (and Linear); other hosts are tunnelled uninspected. Enforcing it needs `CAP_NET_ADMIN`, so rootless deployments cannot.
- Each agent's process can read its mode-scoped GitHub App token; the `gh` wrapper injects it. Opening and merging pull requests are refused at the proxy and go through `hive-open-pr` and `hive-merge` relays. Model keys are swapped for placeholders (`sk-hive-<agent>`) only for gateway backends; Claude and Copilot CLIs hold their own credentials.
- Opt-in: a credential-free sandbox (rootless Podman or a Kubernetes Job, `sandbox.runtime: job`) with a push broker that scans the diff and mints a short-lived token. It needs `agent_sandbox.enabled` and a per-agent `sandbox.enabled`. Proxy-side token injection (`HIVE_PROXY_INJECT_GH_AUTH`) is also opt-in.
- The site says "No agent receives a GitHub token"; the repository's own security model contradicts it on the default path. The docs crawl lists eleven such contradictions between the websites and the repository ([1-docs-crawl.md §12](evidence/2026-10-27-hive/1-docs-crawl.md)).
- Compare [Ploeg ADR-0034](../../apps/ploeg/docs/adrs/0034-the-harness-gets-placeholders-the-worker-keeps-credentials.md) and [ADR-0138](../../apps/ploeg/docs/adrs/0138-a-harness-runs-in-its-own-container-and-no-credential-enters-it.md): one pod per Run, the harness in its own container with no credential in it.

### 1.6 Maturity and governance

- Apache-2.0, DCO, no CLA. Five maintainers, lazy consensus, supermajority for breaking changes. Three release lines: v4 frozen (end of life 21 December 2026), v5 stable since 21 September, v6 in development on the `edge` channel.
- Started 17 April 2026 as `kubestellar/hive`; moved to `hivecommons/hive` on 3 September, partly over the name clash with Apache Hive. CNCF Sandbox application [cncf/sandbox#516](https://github.com/cncf/sandbox/issues/516), vote passed 28 September.
- Sponsors are in-kind: CNCF cloud credits (Akamai/Linode for CI, Oracle OKE for the hub) and CNCF maintainer Copilot seats. No evidence of cash funding, or of a Cloudflare or Bluehost sponsorship beyond ordinary plans.
- 3,572 Go test files, 75 CI workflows, 11 required checks on `v5`.
- Adoption that shipped: kubestellar/console (4,179 pull requests from the Hive App), Project Bluefin (951), Frostyard (29). Claimed without visible activity from this App: tuna-os, Open Horizon.
- Critiques: the volume is beyond human review; attribution is blurred (Anderson authored 6,466 pull requests, over 1,150 of his commits are co-authored by Copilot, and the Outreach agent works under his account despite the README's "agents run as a GitHub App, not your PAT"); the Outreach agent targets 200 "awesome" lists under an anti-spam ruleset it wrote itself; every performance figure is self-reported from the author's own projects.
- Name collisions to keep apart: Apache Hive, OpenShift Hive, Hive Moderation (thehive.ai), the Hive blockchain, TheHive (StrangeBee), and aden-hive/hive, an unrelated multi-agent framework.

## 3. Component by component

- **Ploeg dispatch and shift engine — competing.** Hive's governor, claims, review swarm and fix loop do Ploeg's job for GitHub. It lacks Ploeg's lease per branch, authorized budget and per-Run pod. Nothing in Hive could sit under Ploeg as a harness: it is a control plane that drives the same CLIs Ploeg drives.
- **Ploeg harness adapters — orthogonal.** Both drive Claude Code, OpenCode, Goose and OpenHands. Hive drives Codex and Copilot CLI, which Ploeg does not ([acp-profiles.md](../../apps/ploeg/docs/contracts/acp-profiles.md) says "Codex is not a profile yet"). Hive types into a long-lived CLI's prompt; Ploeg starts a fresh Run per task.
- **Unfold Now, Work Item page and Run cards — competing.** Hive's dashboard shows tracker columns, evidence cards, cost by work item and a web terminal. Its plain-language outcome cards cover the same ground as Unfold's Run cards, aimed at the README reader instead of the reviewer.
- **unfold-mcp and ploeg-mcp — orthogonal.** Hive's v5 MCP is a read-only public knowledge endpoint; its admin and task MCP servers are v6 only.
- **Self-improvement — the same bet, further along.** Hive builds itself: 2,451 pull requests merged into Hive in October, and agents authored 857 of the 1,455 merges its review swarm judged across its repositories. Unfold's [self-improvement design](../../apps/unfold/docs/design/self-improvement.md) is proposed, and GAP-04 in the [gap register](../../apps/unfold/docs/design/gap-register.md) says self-improvement "has no protected release lane". Hive's workflow-path fence and self-authorization hold are concrete answers to that gap.

## 4. Where it competes and where it does not

**It competes** for a GitHub-only open-source maintainer, or a small team on GitHub, who wants agents on chores today, free, under a CNCF badge and an Apache licence. Hive is ahead of Unfold there on reach, published numbers and a ladder that lets a person start at "open pull requests only" and turn it up.

**It does not compete** for the customer Unfold is for ([who Unfold is for](../concepts/who-unfold-is-for.md)): an agency on Forgejo or GitLab that must keep each client's spend, credentials and repositories apart, and that sells delivered work rather than agent time. Hive cannot run on Forgejo or GitLab, has no budget that is checked before spend, gives the agent its token by default and has one organisation per hive.

**The tension:** Hive's L6 merges on green. Unfold's rule is that a person always merges. Matching Hive's dial up to L6 would break that rule; borrowing the dial up to L5 does not.

## 5. Design worth mining

Each item names what Hive does and the Unfold or Ploeg seam it would land in. None of these needs a Hive dependency.

1. **One autonomy dial over the knobs.** A Team-level level that sets `Role.Writes`, `CreatedWork.AutoDispatch`, `forgeFollowUps` and the ACP `permissionMode` together, capped below merge. It belongs in the Team manifest of [ADR-0110](../../apps/ploeg/docs/adrs/0110-a-team-is-ploegs-own-manifest-of-charter-crew-permissions-intake-and-skills.md) as a Ploeg contract, so the person sees one setting and the knobs stay the enforcement.
2. **A path fence for CI and agent configuration.** Refuse a Run's push that touches `.forgejo/workflows/**`, `.github/workflows/**` or `AGENTS.md` unless the Team allows it, and mark the pull request for an owner. Ploeg's push fence (`pkg/worker/pushfence.go`) checks ref updates only.
3. **A self-authorization hold.** Work Items that a Run created and a person never approved should not reach "ready" on their own. Ploeg's created-work limits (`CreatedWork.AutoDispatch`) start such items `proposed` or `queued`; the hold would cover the pull request, not the item.
4. **Input screening before a Run reads a ticket.** Screen ticket text, comments and fetched files for planted instructions, with canaries and an evaluation set whose catch rate is published as a self-run test. This is the empty row in the layer map.
5. **Answers on the forge.** Let a person answer a `needs_human` question or approve proposed work with a comment on the pull request or issue, attributed to that person (ADR-0108 requires the person and channel).
6. **A published outcome benchmark.** Per-merged-item cost, change-failure rate and time to merge, with n and Wilson intervals, minimum bases before a number goes on the site, and a mediated versus unmediated split. It would replace the single n = 3 figure in [cost per merged Work Item](2026-10-11-cost-per-merged-work-item.md) and give the site claims a source.

Not worth mining: long-lived tmux agents with typed kicks (Ploeg's fresh Run per task is the safer shape), one shared container, after-the-fact budgets, the Outreach agent, and leaderboards and achievements, which pull against [ADR-0010](../adr/adr-0010-pull-requests-are-small-whole-and-explained.md)'s small, whole, explained pull requests.

## 6. Implementation path, cheapest first

1. **Now, docs only:** add Hive and Fullsend to the competitor ledger ([market landscape](../../apps/unfold/docs/research/market-landscape.md)). Done with this record.
2. **Small, Ploeg:** the path fence (item 2) and the self-authorization hold (item 3), each as a Ploeg ADR and contract change upstream, since Ploeg is changed in ploeg-hq.
3. **Medium, Ploeg:** the autonomy dial (item 1) inside ADR-0110 when the Team manifest is built; forge answers (item 5).
4. **Medium, both:** input screening (item 4) as a Ploeg stage before prompt assembly, with Unfold showing what was screened.
5. **When there is volume:** the outcome benchmark (item 6), once enough Work Items have merged for bases of at least 200.

**Never:** run Unfold's Work Items on Hive; let an agent merge; make spend a report instead of an authorization.

## 7. Recommendations

1. Record Hive and Fullsend in the competitor ledger now (this change).
2. Run a separate fit survey of Fullsend before any positioning work: Hive names it as the closest open-source rival, and it already supports Forgejo and GitLab, which Hive does not.
3. Open owner decisions for mining items 1 to 4 as tickets on the Glide board. They change Ploeg, so they go upstream as ADRs.
4. Keep "a person always merges" and say so where Unfold is compared with Hive: it is the clearest difference a buyer will see.
5. Treat Hive's published numbers as self-reported. Do not quote "US$ 2 per merged PR" against Unfold's figure until both have comparable bases and definitions.

## 8. Re-evaluation triggers

Any one of these reopens this record:

1. Hive's docs say GitLab or Forgejo are supported for running a hive ([#14096](https://github.com/hivecommons/hive/issues/14096) closes, or `getting-started.md` drops "not supported for running a hive").
2. The credential-free sandbox becomes the default (`agent_sandbox.enabled` defaults on in `hive.yaml.example`), or a budget is checked before a kick starts.
3. Hive publishes pricing for the hosted hub, or a tenant boundary for more than one organisation per hive.
4. A named adopter outside the maintainers' own organisations shows Hive App activity on GitHub.
5. Fullsend's survey (recommendation 2) finds it overlaps Unfold more than Hive does.

## 9. What the sweep found in Unfold

- The contract bundle lacks tests, migrations and the Helm chart, so chart defaults (the strict isolation profile, the separate harness container, the NetworkPolicy) cannot be checked from this repository.
- [Inside a Run](../concepts/inside-a-run.md) says the adapter registry "builds one of four"; there are five.
- The `explain-a-dependency-update` skill cites Ploeg ADR-0106 for reading Renovate pull requests; the matching ADR is [0109](../../apps/ploeg/docs/adrs/0109-a-pull-request-someone-else-opened-is-read-by-a-team-on-the-pull-request.md).
- No Unfold view consumes Ploeg's knowledge-note review queue (`GET /operator/knowledge/reviews`).

## 10. Limits

- Hive's numbers are self-reported from its own spoke; nothing here re-measured them.
- No Hive code was run; the claims about enforcement come from reading code and documentation.
- GitHub's API rate limit cut off two counts (Bluefin's merged bot pull requests and a sample of their titles).
- LinkedIn and X posts were not checked.
- The seam map read the rc.64 bundle; only the Ploeg claims cited in sections 2 and 5 were re-checked against the pinned rc.81.
