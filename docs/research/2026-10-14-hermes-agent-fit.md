# Hermes Agent × Unfold: fit record

Date: 14 October 2026, against `origin/development` at `7575e4d3` with Ploeg pinned at `v0.2.0-rc.21`, and Hermes Agent `v0.22.0`, released the same morning. This is a record. It changes no decision by itself. Its condensed verdict is a dated note on [Ploeg ADR-0032](../../apps/ploeg/docs/adrs/0032-keep-the-dispatch-plane-and-compete-on-authorized-spend.md) ([ploeg-hq #138](https://github.com/ploeg-hq/ploeg/pull/138)), this record landed through [Unfold #380](https://forgejo.webgrip.dev/webgrip/unfold/pulls/380), and what it proposes is on the board as the tickets in [section 10](#10-tickets-filed). The [glossary](../reference/glossary.md) defines each capitalised term.

> **Method.** Four research agents ran in parallel: a crawl of 139 Hermes documentation pages plus its README, `SECURITY.md`, `pyproject.toml` and the Nous Portal pages ([1-docs-crawl.md](evidence/2026-10-14-hermes-agent/1-docs-crawl.md)); a source dig of `NousResearch/hermes-agent` through the GitHub API and a read-only shallow clone ([2-repo-dig.md](evidence/2026-10-14-hermes-agent/2-repo-dig.md)); an ecosystem and absence sweep ([3-ecosystem-and-absences.md](evidence/2026-10-14-hermes-agent/3-ecosystem-and-absences.md)); and a read-only seam map of this repository ([4-seam-map.md](evidence/2026-10-14-hermes-agent/4-seam-map.md)). Downloaded pages were treated as data, never run. These claims were checked first-hand rather than taken from an agent: the GitHub numbers (a first read on 13 October found 253,384 stars and v0.21.7; the sweep's read on 14 October found 253,549 and v0.22.0); the Nous Portal pricing, Business and Cloud pages; the Kanban page's sentences on single-host design and tenants; `harness.MergeDropBox` in [dropbox.go](../../apps/ploeg/pkg/harness/dropbox.go) copying every drop-box field except learnings; the exact protocol-version check in Ploeg's [ACP adapter](../../apps/ploeg/pkg/harness/adapters/acp/acp.go); the meaning of `use_unstable_protocol` in the ACP Python SDK's `core.py` (it switches on unstable methods, not another version number); ADR-0070's re-evaluation trigger; and the two files in this repository that already mention Hermes. No Hermes process was started and no model call was made.

## Verdict

**Hermes Agent is an adjacent product, not a dependency and not a substitute. Do not run Unfold's work on it. Mine its design, meet it from above over MCP, and bench it as an ACP harness only if a free handshake probe passes.**

Hermes is one person's always-on agent: it lives in chat apps, remembers across sessions and writes its own skills. The only part of it that overlaps Ploeg is its Kanban board, and that board is, in its own words, "deliberately single-host", with no money budget, no tenant boundary and no forge beyond GitHub. It fails the test [ADR-0041](../../apps/ploeg/docs/adrs/0041-the-openai-agents-api-stays-outside-the-run-until-it-takes-an-authorized-budget.md) applied to the OpenAI Agents API, that an agent platform under a Run must take an authorized budget, and it trips none of the triggers in [ADR-0032](../../apps/ploeg/docs/adrs/0032-keep-the-dispatch-plane-and-compete-on-authorized-spend.md). The one place it can matter to Unfold is north of Ploeg, as a client a developer already talks to.

The two verdict axes, stated separately:

* **Maturity** is high in volume and low in breadth. Hermes ships a tested release about every three days, has roughly 5,700 test files and gates releases on them. Four people commit 89.5 % of it, it carries 15,320 open issues and 33,193 open pull requests, it has no contributor agreement, and its hosted service is a US company whose terms take a training licence on customer data.
* **Fit** decides. Hermes claims the seams Ploeg deliberately leaves to the person (memory, agent-written skills, a chat gateway) and claims Ploeg's own seam without the properties Ploeg exists for: admission before spend, a credential the agent cannot bypass, a lease under a budget, and a tenant boundary.

**Absences.** Across Hermes' documentation, code and issue tracker there are zero mentions of Vikunja, KEDA, Kata Containers or `agent-sandbox`. Forgejo and Gitea appear only as brand icons in the desktop app. LiteLLM is not a dependency in any form: Hermes removed the litellm library after the March 2026 supply-chain compromise and documents a LiteLLM proxy only as one provider path a user runs. ClickUp, Linear, Jira and GitLab appear only as entries in its MCP server catalogue. Unfold, Ploeg and Omnigraph are absent. Three name collisions to keep apart: the Hermes 4 model family (which Hermes' own docs say is "not recommended for use inside Hermes Agent"), HashiCorp's unrelated Hermes document tool, and an open Hermes pull request that adopts Google's Open Knowledge Format, which is not the OKF of [ADR-0021](../adr/adr-0021-agents-are-briefed-from-a-per-tenant-knowledge-base-exchanged-as-okf.md).

Summary:

1. **What it is.** A Python agent (MIT, Nous Research) with a CLI, desktop apps, a gateway to more than twenty messaging platforms, an ACP server for editors, an OpenAI-compatible API server, cron, subagents, and a learning loop that writes memory and skills without review by default ([section 1](#1-what-hermes-agent-is)).
2. **The overlap is Kanban.** A SQLite board whose dispatcher spawns one `hermes -p <profile> chat -q` process per card on the same host, with git worktrees, an iteration budget, a circuit breaker, a review lane and, for GitHub only, a completion contract that refuses "done" until the pull request's required checks are green ([1.2](#12-the-kanban-board)).
3. **Money.** Hermes itself enforces no money cap anywhere; its budgets are turn, tick and wall-clock counts. Money caps exist only in the hosted Nous Portal, per month and per member ([1.3](#13-money-and-limits)).
4. **Isolation.** Hermes states that it is "a single-tenant personal agent" and that "the only security boundary against an adversarial LLM is the operating system". Its Kanban tenant is "a soft filter". Dangerous-command checks are skipped inside containers because "the container itself is the security boundary" ([1.4](#14-security-and-isolation-in-its-own-words)).
5. **Learning is the opposite bet.** Hermes writes skills and memory from experience, automatically, and loads them next session; a review gate exists but is off by default. Ploeg's [ADR-0066](../../apps/ploeg/docs/adrs/0066-a-runs-learnings-are-proposals-a-person-reviews-before-any-run-sees-them.md) puts a person between a model's note and every later prompt ([1.5](#15-the-learning-loop)).
6. **North is where it fits.** Hermes is an MCP client with stdio and HTTP servers in its configuration, so it can call `unfold_now` and `unfold_get_work` today. Once the planned submit route exists, it can hand governed work to Ploeg ([section 4](#4-the-one-honest-scenario)).
7. **As a harness: possible, unproven, low value.** Ploeg's `acp` adapter runs any stdio ACP agent from a profile, and Hermes serves ACP. A profile would have to switch off what makes Hermes Hermes. Worth one free handshake probe and, if that passes, a six-Run bench ([section 6](#6-implementation-path-cheapest-first)).
8. **Found in Unfold along the way.** Learnings written to the outcome drop box never reach the review outbox, a static finding to verify by test; a writing Run is never told how much budget it has; ADR-0070's re-evaluation trigger looks met in code; four pages drifted from the pinned code ([section 9](#9-what-the-sweep-found-in-unfold)).

## 1. What Hermes Agent is

### 1.1 Self-description and surfaces

Hermes calls itself "the self-improving AI agent built by Nous Research. It's the only agent with a built-in learning loop" ([README](https://github.com/NousResearch/hermes-agent/blob/main/README.md)), "one agent, one memory, every surface" ([homepage](https://hermes-agent.nousresearch.com/)) and, in its own skill for operating itself, "in the same category as Claude Code (Anthropic), Codex (OpenAI), and OpenClaw" ([bundled hermes-agent skill](https://hermes-agent.nousresearch.com/docs/user-guide/skills/bundled/autonomous-ai-agents/autonomous-ai-agents-hermes-agent)). `SECURITY.md` says "Hermes Agent is a single-tenant personal agent".

Its surfaces, all over one `AIAgent` loop ([architecture](https://hermes-agent.nousresearch.com/docs/developer-guide/architecture)):

| Surface | What it is | Relevant to Unfold as |
| --- | --- | --- |
| CLI and TUI, desktop apps | The interactive agent; Python 3.14, macOS Apple Silicon and Windows MSIX desktop builds | Where a developer might already live |
| Messaging gateway | One long-running process for 25+ platforms: Telegram, Discord, Slack, WhatsApp, Signal, Matrix, email and more; user allowlists and DM pairing | The "lives where you do" bet |
| ACP server | `hermes acp`, an Agent Client Protocol agent over stdio for VS Code, Zed, JetBrains and Block's Buzz; `agent-client-protocol==0.9.0` | A candidate harness under Ploeg's `acp` adapter |
| API server | OpenAI-compatible `POST /v1/chat/completions` and `/v1/responses`, plus a Runs API with SSE events and approval answers; `API_SERVER_KEY` required | A way for a program to drive Hermes |
| MCP client | Stdio (`command`, `args`, `env`) and HTTP servers in `config.yaml`, with OAuth | How Hermes reaches `unfold-mcp` and `ploeg-mcp` |
| `hermes mcp serve` | A messaging bridge: ten tools to read conversations, send messages and answer approvals from another MCP client. Not the agent's own tools | Not a way to invoke Hermes |
| A2A plugin | Agent2Agent 1.0 in both directions, off by default, localhost-only without a token | The ADR-0007 facade's "real A2A client" |
| Kanban | See 1.2 | The overlap with Ploeg |
| Batch runner | Trajectory generation for training data, with checkpoints and toolset distributions | The research use that shaped the project |

Hermes first shipped on 25 February 2026, ten days after OpenClaw's creator joined OpenAI, into the same "always-on personal agent on your server" category, with a one-command importer for OpenClaw homes ([3-ecosystem-and-absences.md](evidence/2026-10-14-hermes-agent/3-ecosystem-and-absences.md), timeline). Nous Research raised a US$ 90 million Series B at a US$ 1,5 billion valuation on 7 October 2026, reported about US$ 36 million in annualised revenue, and estimates that Hermes "drives approximately 2.5% of all global token usage" ([TechCrunch](https://techcrunch.com/2026/10/07/nous-research-confirms-it-hit-1-5b-valuation-launches-ai-agents-for-business-users/), [fundraise note](https://nousresearch.com/a-note-on-our-fundraise)). It is not listed in the [ACP registry](https://agentclientprotocol.com/registry) that Zed and JetBrains discover agents from; four pull requests to add it are open and unmerged.

Hermes is Python with no Go or TypeScript client library. Its PyPI package is stale at 0.19.0 from July; supported installs are its install script, package-manager bundles, Docker, Nix and APT. A third-party Kubernetes operator exists ([hermeum/hermes-agent-operator](https://github.com/hermeum/hermes-agent-operator), 55 stars); Hermes itself has no Kubernetes, Helm, gVisor, Kata or Firecracker code.

### 1.2 The Kanban board

The [Kanban page](https://hermes-agent.nousresearch.com/docs/user-guide/features/kanban) describes "a durable task board, shared across all your Hermes profiles, that lets multiple named agents collaborate on work without fragile in-process subagent swarms. Every task is a row in `~/.hermes/kanban.db`; every handoff is a row anyone can read and write; every worker is a full OS process with its own identity."

What it does, in Ploeg's terms:

* **Intake and decomposition.** A card enters `triage`, `todo` or `ready`. A built-in decomposer, on by default, turns a `triage` card into a graph of child cards assigned to profiles, capped at three cards per tick "so a bulk-load of triage tasks doesn't burst-spend the auxiliary LLM". Ploeg's counterpart is Refinement and "work creates work" ([Ploeg ADR-0031](../../apps/ploeg/docs/adrs/0031-runs-create-work-items-held-for-approval-within-limits.md)).
* **Claim and spawn.** A dispatcher inside the gateway ticks every 60 seconds, claims a `ready` card atomically, and runs `hermes -p <assignee> chat -q <prompt>` as a host process in the card's workspace: a scratch directory, a shared directory, or a git worktree. The claim has a 15-minute TTL and a PID fingerprint; a dead process is reclaimed. Ploeg's counterpart is the Lease, a database row that a KEDA-started pod renews ([ADR-0010](../../apps/ploeg/docs/adrs/0010-shift-owns-the-item-lease-owns-the-branch.md)).
* **Lifecycle.** Statuses `triage | todo | ready | running | blocked | review | done | archived`. A worker must end in exactly one of `kanban_complete`, `kanban_request_review`, `kanban_block`, or die, in which case the kernel records `crashed`, `gave_up` or `timed_out`. Two consecutive spawn failures block the card; a provider credential error trips the breaker on the first occurrence ([worker lanes](https://hermes-agent.nousresearch.com/docs/user-guide/features/kanban-worker-lanes)).
* **Review.** `kanban_request_review` moves a card to `review`; the dispatcher claims it with a bundled `sdlc-review` skill whose rounds read the diff cold, then run it, then audit it against the acceptance criteria; the reviewer approves, requests changes back to the original implementer, or blocks. Ploeg's counterpart is the reading Role and the verdict-driven, capped fix loop ([ADR-0017](../../apps/ploeg/docs/adrs/0017-the-review-loop-is-verdict-driven-and-capped.md)).
* **Budgets.** `agent.max_turns` is "unlimited by default"; when finite, `agent.budget_warning_ratio` (off by default) appends "one model-visible checkpoint notice" near 90 % of it. There is a per-card `max_runtime`, a stale timeout of four hours, and a goal mode that re-prompts a worker until a judge model agrees, with a 20-turn default. None of these is money.
* **Completion contract, GitHub only.** A card declared with `--completion-contract OWNER/REPO` cannot complete until the pull request's required checks on its exact head commit are present and green: "Missing, pending, failed, cancelled, timed-out, stale, skipped or neutral required evidence cannot complete the card." The read runs as the assignee profile's `gh` login. "GitHub Enterprise is not covered." Ploeg's counterpart is [ADR-0059](../../apps/ploeg/docs/adrs/0059-delivery-facts-come-from-the-forge-never-from-the-agents-outcome.md) (the forge decides what was delivered) and [ADR-0070](../../apps/ploeg/docs/adrs/0070-a-pull-request-is-ready-for-review-only-when-its-checks-passed-on-the-pushed-commit.md) (the worker's own verification gates review).
* **Where it stops.** "Kanban is deliberately single-host. `~/.hermes/kanban.db` is a local SQLite file and the dispatcher spawns workers on the same machine. Running a shared board across two hosts is not supported." "Tenants are a soft filter; boards are the hard isolation boundary." "This is a single-user lifecycle guard, not OS isolation against arbitrary direct database writes." "Auto-assignment, budgets, governance gates, and org-chart views remain user-space." Wrapping Codex, Claude Code or opencode as a worker lane is "not yet a paved path"; today Hermes drives those CLIs through its own terminal tool from bundled skills.

Open issues show where its users push: distributed workers with a central board ([#29244](https://github.com/NousResearch/hermes-agent/issues/29244)), a pluggable board provider ([#61459](https://github.com/NousResearch/hermes-agent/issues/61459)), database corruption under concurrent workers ([#53819](https://github.com/NousResearch/hermes-agent/issues/53819)), a PostgreSQL session store ([#23717](https://github.com/NousResearch/hermes-agent/issues/23717)), a per-session token budget ([#91713](https://github.com/NousResearch/hermes-agent/issues/91713)) multi-tenancy ([#34352](https://github.com/NousResearch/hermes-agent/issues/34352), [#85497](https://github.com/NousResearch/hermes-agent/issues/85497): `HERMES_TENANT` has no memory-isolation effect), a Forgejo or Gitea card that "can never complete" because completion contracts are GitHub-only ([#135330](https://github.com/NousResearch/hermes-agent/issues/135330)), a Kubernetes session-pod backend that names Kata and `agent-sandbox` ([#79869](https://github.com/NousResearch/hermes-agent/issues/79869)), and the maintainer's own open proposal from March for a Symphony-style poll, dispatch, resolve and land loop over an issue tracker ([#404](https://github.com/NousResearch/hermes-agent/issues/404)).

### 1.3 Money and limits

Hermes enforces no per-task, per-session, per-profile or per-run money cap. A grep over its documentation for cost caps finds only Claude Code's own `--max-budget-usd` flag inside a bundled skill, a cost filter on `hermes sessions prune`, and the portal's monthly cap display. Spend is reported, not bounded: an estimated cost per session, a status-bar figure, `hermes insights`, and a usage file. Two open issues say the estimate understates real billing by several times ([#108936](https://github.com/NousResearch/hermes-agent/issues/108936), [#87450](https://github.com/NousResearch/hermes-agent/issues/87450)). Credential pools rotate to the next API key on a 402.

Money caps exist only on the hosted side. Nous Portal subscriptions are Free, Plus (US$ 20 a month with US$ 22,00 in credits), Super (US$ 100, US$ 110,00) and Ultra (US$ 200, US$ 220,00) ([homepage](https://hermes-agent.nousresearch.com/)). Hermes Cloud runs a dedicated instance for US$ 0,51 a day (Standard) or US$ 0,99 (Pro), inference and tools billed on top ([Cloud](https://portal.nousresearch.com/cloud)). Hermes Business is "a shared Hermes deployment for your whole team: one balance, hosted agents for every member", where "members draw from it with per-member spend caps you set" ([Business](https://portal.nousresearch.com/business)). Enterprise "runs on infrastructure you control, with SSO, SLAs, and white-glove onboarding", price on request.

Set against [ADR-0012](../../apps/ploeg/docs/adrs/0012-two-level-budgets-authorized-and-settled.md): Ploeg authorizes `min(roleCap, remaining)` before a Run starts, mints a LiteLLM key capped at that amount, blocks it on every exit path and settles the real cost afterwards. Hermes has no equivalent at any layer. Its per-member cap is the shape of Unfold's Agency and Client Budgets in [ADR-0006](../adr/adr-0006-the-ticket-is-the-billing-unit.md), one level up from the Run.

### 1.4 Security and isolation, in its own words

[`SECURITY.md`](https://github.com/NousResearch/hermes-agent/blob/main/SECURITY.md) is unusually candid:

> The only security boundary against an adversarial LLM is the operating system. Nothing inside the agent process constitutes containment — not the approval gate, not output redaction, not any pattern scanner, not any tool allowlist.

> Within the authorized set, all callers are equally trusted. Hermes Agent does not model per-caller capabilities inside a single adapter. Operators who need capability separation should run separate agent instances with separate allowlists.

The mechanics ([security page](https://hermes-agent.nousresearch.com/docs/user-guide/security)): a command-approval gate with modes `smart` (an auxiliary model judges risk), `manual` and `off`, plus `--yolo`; 102 dangerous-command patterns and 14 hardline patterns no setting bypasses; headless surfaces (cron, webhooks, the API server) deny by default. Seven terminal backends: local (the default, no sandbox), SSH, Docker, Singularity, Modal, Daytona and Vercel Sandbox. "When running in docker, singularity, modal, daytona, or vercel_sandbox backends, dangerous command checks are skipped because the container itself is the security boundary." The Docker backend drops all capabilities but three, sets `no-new-privileges`, a PID limit and size-limited tmpfs, and sets no seccomp, AppArmor or user-namespace flags. Secrets are stripped from child processes by name; an optional `iron-proxy` injects real keys at egress for the Docker backend only. Audit is partial: Kanban events and worker logs, an A2A audit file, approvals recoverable from the session database; no central or tamper-evident log of tool calls.

Open issues in this area include an `execute_code` sandbox escape marked P1 ([#101036](https://github.com/NousResearch/hermes-agent/issues/101036)), background terminal commands bypassing the approval gate ([#90789](https://github.com/NousResearch/hermes-agent/issues/90789)), and agent-created skills publishable before a fail-closed scan decision ([#84250](https://github.com/NousResearch/hermes-agent/issues/84250)).

The record outside the tracker: NVD lists 39 CVEs against `hermes-agent` published between April and September 2026, most low or medium, with one GitHub-reviewed HIGH (CVE-2026-53869, DNS rebinding past the WebSocket origin check, fixed in 0.16.0) and one that SentinelOne describes as a tenant-isolation break in session lookup to which the vendor "did not respond to disclosure attempts" (CVE-2026-11461). An independent audit filed in April ([#7826](https://github.com/NousResearch/hermes-agent/issues/7826): "default security posture is ALLOW-ALL") is still open with no comment. Hermes' Skills Hub pulls from OpenClaw's ClawHub, where Koi Security found 341 malicious skills among 2,857 in February 2026; Hermes' own scanner is regex-based and its advisory evaluator is "silently skipped" when its binary is absent. The Cloud Security Alliance's [research note](https://labs.cloudsecurityalliance.org/research/csa-research-note-hermes-agent-cves-20260504-csa-styled/) and Repello's [threat model](https://repello.ai/blog/hermes-agent-security) are the only outside reviews found; none from a firm that has audited the harnesses Ploeg runs.

Set against Ploeg: a Run executes in its own pod, on the homelab in a Kata micro-VM; the worker holds the credentials and the harness gets placeholders behind loopback proxies ([ADR-0034](../../apps/ploeg/docs/adrs/0034-the-harness-gets-placeholders-the-worker-keeps-credentials.md), [worker control](../../apps/ploeg/docs/contracts/worker-control.md)); the push token is fenced to the Run's branch; a leaked key fails the Run; and a Tenant is a namespace, a default-deny network and a budget ([ADR-0017](../adr/adr-0017-a-tenant-sits-above-teams-and-bounds-what-users-sources-and-budgets-reach.md), not implemented yet). The two projects answer different questions. Hermes asks how one trusted person keeps an agent from wrecking their own machine. Ploeg asks how several people share a cluster, a budget and a forge with agents none of them fully trusts.

### 1.5 The learning loop

Hermes' central claim is that it "creates skills from experience, improves them during use, nudges itself to persist knowledge, searches its own past conversations, and builds a deepening model of who you are across sessions". The mechanics ([skills](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills), [memory](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory)): the system prompt asks the agent to record any non-trivial workflow with `skill_manage`; every ten tool iterations a forked review agent decides whether to write a skill, and every ten prompts whether to write memory, at roughly 30,000 tokens per review; `MEMORY.md` and `USER.md` are capped at 2,200 and 1,375 characters and injected into every session's system prompt; a curator archives unused skills; "the agent can modify or delete any skill". A write-approval gate exists for skills and memory and is off by default; a content guard for agent-created skills is off by default because it "was tripping the heuristic too often". Hub-installed skills do pass a security scanner, with trust levels for official and community sources.

This is the exact failure [ADR-0066](../../apps/ploeg/docs/adrs/0066-a-runs-learnings-are-proposals-a-person-reviews-before-any-run-sees-them.md) is written to prevent: "one wrong or injected note reaches every later Run". For one person on their own machine, Hermes' trade is reasonable and the gate is a setting away. For an agency running client code under budget, it is not: a skill written during one client's Run would steer the next client's Run. Unfold's shape stays: knowledge packs selected by term match ([ADR-0065](../../apps/ploeg/docs/adrs/0065-a-run-is-briefed-with-an-okf-knowledge-pack-written-outside-the-clone.md)), skills named per Work Item by a deterministic matcher ([ADR-0083](../../apps/ploeg/docs/adrs/0083-a-run-is-told-which-skills-bear-on-its-work-item.md)), learnings as proposals a person accepts. Section 9 records that the proposal channel is currently broken for drop-box harnesses.

### 1.6 Hosted offerings, terms and data

Self-hosted Hermes keeps everything under `~/.hermes/` and sends prompts only to the configured provider. The hosted side is different. Nous Portal's [terms](https://portal.nousresearch.com/terms) contract with Nous Research, Inc., a Delaware corporation, with disputes arbitrated in Cupertino; section 12.3 grants Nous "a non-exclusive, worldwide, royalty-free, fully paid-up, transferable, and sublicensable license" to process customer data "for the purposes of … training, fine-tuning, refining, grounding, evaluating, developing, operating, testing, and enhancing machine learning and artificial intelligence models", unless the privacy policy's Privacy Mode is enabled. The terms choose California law and arbitration in Cupertino, keep customer data for six months after termination, and name sub-processors only on request. Neither the terms nor the [privacy policy](https://portal.nousresearch.com/privacy) names a storage location, an EU transfer mechanism, a data processing agreement (the portal's `/dpa` path answers 404) or GDPR rights; the 139 documentation pages contain no mention of GDPR, EU residency, a DPA, SOC 2 or ISO 27001. Hermes Cloud picks "the location closest to you that has availability" from fourteen cities, Amsterdam, Frankfurt, Paris, Stockholm and London among them, without a residency guarantee. Business data lives "in an isolated tenant per team on Nous infrastructure"; Enterprise keeps it on the customer's own. Nous says Hermes is "already trusted by some of the world's largest companies" and names none, in its launch post, its fundraise note or its press.

For the agency offering in [ADR-0005](../adr/adr-0005-unfold-is-offered-to-agencies.md) and [ADR-0009](../adr/adr-0009-one-tenant-per-agency.md), which promises an EU cluster and one Tenant per Agency, none of the hosted Hermes tiers is a component to build on. Hermes Enterprise is the nearest comparator for "self-hosted with SSO", and it publishes no price.

## 3. Component by component

* **ploegd (dispatch, budgets, keys).** Competing in shape with Hermes Kanban, orthogonal in deployment. Both admit work, claim it, spawn a worker, reclaim a dead one and route to review. Ploeg's claim sits under admission and a budget, survives a dead pod, and records every step as rows an operator can read ([ADR-0005](../../apps/ploeg/docs/adrs/0005-build-a-dedicated-dispatch-plane.md)). Hermes' sits in one person's home directory and trusts the process that holds the file.
* **ploeg-worker and the harness seam.** Complementary, conditionally. `harness.Adapter` and the `acp` adapter's profiles ([profiles.go](../../apps/ploeg/pkg/harness/adapters/acp/profiles.go), [ACP profiles contract](../../apps/ploeg/docs/contracts/acp-profiles.md)) accept any stdio ACP agent. The seam map's section 2.7 lists what a `hermes` profile would need: the command, `OPENAI_BASE_URL` and `OPENAI_API_KEY` placeholders under the loopback proxy (Hermes reads exactly those two names), a per-Run `HERMES_HOME` under the scratch home with a `config.yaml` that holds no key, the `memory` and `skills` toolsets disabled, approval mapped from the permission mode, and every MCP server, plugin and web tool switched off. Two facts must be probed first: Ploeg fails a Run unless the agent's `initialize` answer carries exactly Ploeg's protocol version number, and Hermes starts its adapter with `use_unstable_protocol=True`, which switches on the SDK's unstable methods; whether its advertised version matches is a free handshake away from known. Everything Hermes adds, memory, skills, sessions, dies with the pod's `emptyDir`, which is as it should be. Two control planes already do this: Multica runs Hermes as an ACP agent with a per-task home (`server/internal/daemon/execenv/hermes_home.go` and siblings), and Omnigent ships a Hermes harness behind its policy hook. Multica's users report the cost: a per-task `HERMES_HOME` "rebuilds a ~720 MB dependency environment on every launch" ([#137135](https://github.com/NousResearch/hermes-agent/issues/137135)), so a Team image would have to bake Hermes' environment and point only the data home at the scratch directory.
* **The LiteLLM seam.** Absent in Hermes. There is no gateway hook, so a Hermes-run Run would be governed only through the key Ploeg mints, which is the same position as every other harness and is fine. Separately, Hermes' `CONTRIBUTING.md` records removing its litellm dependency after a supply-chain compromise in March 2026; whether the LiteLLM proxy version the homelab runs was affected is not checked here, and belongs to [ADR-0008](../../apps/ploeg/docs/adrs/0008-litellm-is-the-credential-and-metering-seam.md)'s review, due 2026-10-31.
* **Tracker and forge seams.** Orthogonal. Hermes has no `TrackerProvider` or `ForgeProvider` shape; its tracker is its board, its forge is `gh`. Vikunja: zero hits. Forgejo: a brand icon.
* **Knowledge and skills.** Competing bets, see 1.5. Transferable: the Skills Hub's install-time scanner and trust levels, and the curator's stale-to-archived lifecycle, both of which [2026-10-13-sharing-agent-skills.md](../../apps/ploeg/docs/research/2026-10-13-sharing-agent-skills.md) and [ADR-0092](../../apps/ploeg/docs/adrs/0092-a-team-pins-its-skills-in-a-catalogue-that-ploegd-fetches-once-and-serves-by-digest.md) already weighed; the catalogue's chosen control is a content hash in a reviewed lockfile plus a host allowlist, which is stricter than a scanner.
* **The Unfold application.** Competing for the same person's attention, not for the same job. Unfold is where a Team's Work Items are followed, reviewed and steered under one authority ([ADR-0002](../adr/adr-0002-ploeg-is-the-only-engine.md)). Hermes is where one person's agent answers them in Telegram. The product lesson is that reach matters: the open ticket to notify the owner when a Work Item enters `needs_human` ([VIK-562](https://vikunja.webgrip.dev/tasks/562)) is Unfold's version of "lives where you do".
* **The VS Code extension and AHP.** Orthogonal. Unfold hosts Agent Host Protocol sessions for VS Code's Agents window; Hermes is an ACP agent for editors. [Ploeg ADR-0006](../../apps/ploeg/docs/adrs/0006-ahp-is-the-wrong-layer.md) keeps AHP out of the harness boundary; Hermes neither helps nor hurts there.
* **unfold-mcp and ploeg-mcp.** Complementary now. Hermes runs stdio MCP servers with `command`, `args` and `env`, so [Ask Unfold and Ploeg from an AI client](../how-to/ask-from-an-ai-client.md) applies to it as soon as someone verifies the environment handling. Hermes' own `hermes mcp serve` is a messaging bridge, not an entry point to its agent, so the reverse direction, Unfold driving Hermes, would go through its API server or ACP, and there is no reason to want it.
* **The site and the offering.** Hermes is a free MIT agent with a US$ 20 to US$ 200 subscription for models and tools, the same credits-plus-subscription pattern the [competitor record](evidence/2026-09-29-agency-pricing/competitors-and-white-label.md) found everywhere. It does not price work. Unfold's Delivery Fee on Acceptance stays structurally different from it, as from the rest.

## 4. The one honest scenario

**Hermes north of Ploeg: the developer's personal agent as a front door to governed work.** A developer who already talks to their Hermes from a phone asks it what waits for them in Unfold; Hermes calls `unfold_now`, reads the reason and the fix, and later, once the submit route exists ([Unfold ADR-0023](../../apps/unfold/docs/adrs/0023-unfold-submits-work-to-ploeg-and-never-executes-it.md), [VIK-1189](https://vikunja.webgrip.dev/tasks/1189)), proposes a Work Item that enters as `proposed` and waits for a person to approve, exactly as the MCP record decided ([2026-09-29-mcp-access](2026-09-29-mcp-access.md)). Nothing Hermes does south of that line is governed, and nothing north of it needs to be.

The tension: Hermes' value is persistence and reach, a memory, a skill library and a session store that grow, and a gateway that is always on. A Ploeg Run is the opposite, stateless, keyless and gone with the pod. Running Hermes inside a Run means switching off what makes it Hermes and paying its startup for a plain ACP loop. Running Ploeg's work on Hermes' board means giving up admission before spend, the lease under a budget, the Tenant and the forge-side truth. The shape that survives is Hermes outside the Run and Ploeg inside it, with MCP between them.

A second, narrower scenario: if a bench shows Hermes' loop cheaper per merged Work Item than opencode or OpenHands on the same model, a `hermes` ACP profile earns a Team. The seam exists; the evidence does not. The only third-party same-model comparison found, a vendor blog's 25-task run on Kimi K3, scored Hermes 20 of 25 at US$ 0,46 per success against Claude Code's 19 of 25 at US$ 1,96 ([Composio](https://composio.dev/content/hermes-agent-vs-claude-code)); it is one run by a party that sells integrations, on a model the [topology record](2026-10-11-agentic-models-and-topology.md) rates poor value, and it measured neither merged pull requests nor review time. It is a reason to run the bench, not a result.

## 6. Implementation path, cheapest first

1. **Document Hermes as an MCP client of Unfold.** One verified configuration block in the how-to, zero spend ([VIK-2047](https://vikunja.webgrip.dev/tasks/2047)).
2. **Probe the ACP handshake.** `hermes acp --check` plus one `initialize` exchange against Ploeg's client, no model call. A version mismatch ends the harness question with the Hermes issue to watch named ([VIK-2043](https://vikunja.webgrip.dev/tasks/2043), first criterion).
3. **If the probe passes, a `hermes` profile and a six-Run bench** against the `opencode` profile on the same model, under US$ 3 of tokens, decided by the owner before it runs (VIK-2043, remaining criteria).
4. **Mine the two designs** through their spikes, VIK-2044 and VIK-2045, whichever the owner pulls first.
5. **If the owner ever runs Hermes personally in the webgrip stack**, that is the "real A2A client lands" trigger of [ADR-0007](../../apps/ploeg/docs/adrs/0007-a2a-adopt-nothing-watchlist-a-facade.md); re-read that record before building anything.

Never:

* Run Ploeg Work Items on Hermes Kanban, or mirror the board into it. Two run-trackers, and the second one has no budget, no tenant and no forge truth.
* Share a Hermes home, memory or skill directory between Runs, Teams or clients. Everything a Run writes under `HOME` dies with the pod by design.
* Let a Hermes-written skill or memory entry reach a Run's prompt without the ADR-0066 review step.
* Route client code or prompts through Nous Portal, Hermes Cloud or Hermes Business. The terms take a training licence, the entity is American, and no residency or DPA is published.
* Treat `HERMES_TENANT` as tenancy. Hermes says it is a soft filter.

## 11. Limits

* Nothing was executed. No Hermes process ran, no ACP handshake was attempted, no Run was spawned. * Press figures (valuation, revenue, token share, "cloned over 24 million times") are Nous' own or reported second-hand; none was checked against a filing. Searches ran in a US locale and surfaced no Reddit thread, which is a gap, not an absence.
